# Teacup Host — программа для управления принтером

Программа для Windows (WPF, .NET 8) — аналог Pronterface (printrun) с
современным интерфейсом в стиле Windows 11 (тёмная тема Fluent,
библиотека [WPF-UI](https://github.com/lepoco/wpfui)). Сделана под
протокол этой прошивки, но работает с любой Marlin-совместимой.

Возможности:

- **подключение** по COM-порту: USB CDC платы Black Pill или USB-UART
  адаптер; есть **виртуальный принтер** — всё можно попробовать без железа;
- **проверка принтера**: перемещение осей, хоуминг, экструдер, обдув,
  скорость и поток (`M220`/`M221`), нагрев хотэнда и стола с графиком,
  концевики (`M119`), позиция (`M114`), настройки (`M503`/`M500`), сетка
  стола (`G29`, `M420 V`), автоподбор PID (`M303`), драйверы TMC (`M122`),
  аварийные команды `M112`/`M410`/`M108`/`M999`, свои макросы;
- **печать с компьютера** через COM-порт: номера строк, контрольные суммы,
  повтор строк по `Resend`, пауза, продолжение, остановка;
- **SD-карта и SPI flash**: список файлов, печать (`M23`/`M24`), пауза
  (`M25`), удаление (`M30`), очистка flash (`M9002`), **загрузка файла на
  flash** (`M28`/`M29`, как «Upload to SD» в Pronterface), прогресс по `M27`;
- **симуляция печати**: модель строится слой за слоем в 3D и на виде слоя,
  сопло двигается по траектории, скорость ×1…×1000, шаг по перемещениям и
  слоям, перемотка ползунком;
- **текущий G-код** — и в симуляции, и при печати (с компьютера и с SD):
  строка подсвечивается в листинге и выводится крупно над моделью вместе с
  координатами и подачей. Щелчок по строке листинга — симуляция до неё;
- консоль с историей команд, фильтром служебных строк и цветами.

## Сборка и запуск

Нужен .NET 8 SDK (Visual Studio 2022 17.8+ или `dotnet` из командной
строки).

```
cd host
dotnet build TeacupHost.sln -c Release
dotnet run --project TeacupHost -c Release
```

Один exe-файл без установки .NET на целевом компьютере:

```
dotnet publish TeacupHost -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -o publish
```

Получается `publish\TeacupHost.exe` (около 75 МБ), его можно просто
скопировать на другой компьютер.

Тесты ядра (разбор G-кода, построение траектории, протокол с виртуальным
принтером: Resend, загрузка `M28`/`M29`, печать с flash, `M112`/`M999`,
`M108`) работают и на Linux:

```
dotnet test TeacupHost.Core.Tests
```

Проект WPF собирается и на Linux (`EnableWindowsTargeting`), но
запускается только в Windows 10/11.

## Структура

| Каталог | Содержимое |
|---------|------------|
| `TeacupHost.Core/GCode` | разбор строк G-кода, файл с байтовыми смещениями строк, построение траектории (слои, дуги `G2`/`G3`, типы экструзии из комментариев слайсера, оценка времени), демо-модель |
| `TeacupHost.Core/Printing` | COM-порт, протокол хоста (`PrinterConnection`), разбор ответов, виртуальный принтер |
| `TeacupHost.Core.Tests` | тесты xUnit |
| `TeacupHost` | приложение WPF: окно, панели, 3D-вид (`Controls/ToolpathViewport`), вид слоя (`Controls/LayerView`), график температур |

## Интерфейс

- **Сверху** — порт, скорость, подключение, температуры, «Открыть»,
  «Демо» и красная кнопка **СТОП (M112)**.
- **Слева** — вкладки: «Печать» (файл, печать с компьютера, загрузка на
  flash), «Оси», «Нагрев», «SD / flash», «Тесты» (проверки, остановка,
  макросы).
- **В центре** — модель: «3D» (левая кнопка мыши — вращение, правая или
  Shift+левая — сдвиг, колесо — масштаб, двойной щелчок — сброс вида) и
  «Слой» (вид сверху на текущий слой, слой ниже — бледным, холостые ходы
  пунктиром). Справа — ползунок слоёв, внизу — управление симуляцией.
  Цвета — по типам экструзии из комментариев `;TYPE:` (PrusaSlicer, Cura,
  SuperSlicer); без них вся экструзия одного цвета.
- **Справа** — листинг G-кода с текущей строкой и консоль.

Файл можно открыть кнопкой, перетащить в окно или передать в командной
строке (`TeacupHost.exe part.gcode`).

## Связь с прошивкой

Программа работает как printcore (модуль связи Pronterface), с учётом
особенностей прошивки (раздел «Связь с хостом» в основном README):

- при подключении включается DTR — без него прошивка считает USB-порт
  закрытым и не отвечает; отправляется `N0 M110 N0*125`, после первого `ok`
  — `M115`, `M155 S2` (температура приходит сама, без `M105` в потоке
  команд), `M105`, `M114`, `M20`;
- каждая строка уходит как `N<n> <команда>*<xor>`, следующая — после
  `ok` предыдущей. На `Error:… / Resend: n / ok` строки отправляются снова
  с номера `n`. Ручные команды встают между строками печати;
- `M112`, `M410`, `M108` уходят сразу, в обход очереди: их разбирает
  аварийный парсер прошивки прямо в прерывании;
- `echo:busy: processing` продлевает ожидание; если 20 с нет ни одной
  строки, программа считает `ok` потерянным и отправляет `M105`;
- `Error:… kill() called!` и другие остановы переводят программу в
  состояние «ОСТАНОВЛЕН»: печать прекращается, доступен `M999`;
- `start` (перезагрузка платы по UART) прерывает печать и заново
  синхронизирует номера строк;
- символы вне ASCII (например, кириллица в `M117`) заменяются на `?`, чтобы
  контрольная сумма совпала с тем, что получит прошивка.

**Остановка печати** (кнопка «Стоп»): строки перестают отправляться (для
SD — `M25`), сразу уходит `M410` (движение прерывается, очередь
сбрасывается), затем скрипт отмены из настроек (по умолчанию
`M104 S0`, `M140 S0`, `M107`, `M84`).

**Пауза при печати с компьютера** только перестаёт отправлять строки.
Если пауза дольше `M86 S` (P3 Steel: 300 с), прошивка решит, что хост
потерян (см. «Потеря хоста» в основном README). Для длинных пауз задайте
`M86 S` больше.

## SD-карта и SPI flash

Вкладка «SD / flash» работает с тем, что настроено в прошивке: SD-картой
(`SD_CARD_SELECT_PIN`) или файлами в SPI flash (`SPI_FLASH_FILES`).

- **Загрузка** (вкладка «Печать», «Загрузить на SD / SPI flash») — `M28
  ИМЯ.GCO`, строки без комментариев, `M29`. Имя в формате 8.3 латиницей.
  На SD-карту прошивка не пишет (Petit FatFs только читает), загрузка
  работает только с SPI flash. Файл с тем же именем заменяется.
- **Текущая строка при печати с SD.** Программа раз в 2 с опрашивает
  `M27` (`SD printing byte n/m`) и по байтовому смещению находит строку:
  - для файлов, загруженных из программы в этом сеансе, — точно (известно,
    что именно записано во flash);
  - для файла, записанного на карту на компьютере, — если в программе
    открыт тот же файл (совпадает размер).

  Иначе показывается только прогресс в байтах.
- Конец печати программа видит по ответу `Not SD printing`.

## Виртуальный принтер

Выберите в списке портов «Виртуальный принтер». Он отвечает как прошивка:
нумерация строк и `Resend`, `ok` на каждую строку, нагрев с инерцией и
`M109`/`M190` с `busy`, `M155`, `M114`, `M119`, движения с буфером
планировщика, `M112`/`M999`, `M108`, файлы flash (`M20`…`M30`, `M28`/`M29`,
`M9002`) с готовым `DEMO.GCO` и печать с flash с `M27`. Поле «×» рядом —
ускорение времени (×10 — печать в 10 раз быстрее настоящей).

## Настройки

Хранятся в `%APPDATA%\TeacupHost\settings.json`: порт и скорость, размер
стола (по умолчанию 220 × 180 × 200 мм, как в `printer.p3steel.h`),
диаметр филамента, подачи для перемещений, предустановки температур,
скрипт отмены (`CancelScript`), макросы. Файл создаётся при выходе из
программы, его можно править вручную при закрытой программе.

## Оценка времени

Время каждого перемещения считается по трапециевидному профилю скорости с
ускорением 1000 мм/с² и скоростью в углах по junction deviation 0,013 мм,
с ограничением скоростей осей (150 / 150 / 4 / 25 мм/с) — как в
`printer.p3steel.h`. `M204` и `M205 J` из файла учитываются. Это оценка:
во время печати оставшееся время уточняется по фактической скорости.
