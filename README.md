# Teacup для STM32F401 / STM32F411 (IAR EWARM)

Порт прошивки Teacup на STM32F401 и STM32F411 (платы WeAct «Black Pill»).
Код от AVR, LPC и PlatformIO удалён. Сборка доступна в IAR EWARM и через GCC на Ubuntu/WSL без лицензии IAR.
Для Teacup Host доступен MSI с рабочей иконкой.

## Тестирование

Запуск тестов в Windows и Linux, автоматическая загрузка компонентов,
покрытие, модели Renode и проверки CI — в [TESTING.md](TESTING.md).

## Сборка рабочей прошивки GCC в Ubuntu / WSL

**Makefile в корне проекта** собирает рабочую прошивку принтера с `config/config.h`
(сейчас Black Pill / P3Steel), а не тестовую конфигурацию Renode.
Существующий `test/gcc/Makefile` остаётся независимым. В каталоге проекта в Linux
или WSL Ubuntu:

```sh
sudo apt-get update
sudo apt-get install -y --no-install-recommends make gcc-arm-none-eabi libnewlib-arm-none-eabi python3
make -j"$(nproc)"                              # F401C, Release
make -j"$(nproc)" CHIP=F411E CONFIG=Debug
make -j"$(nproc)" all-variants                 # все шесть сочетаний чипа и конфигурации
```

| CHIP | Макрос устройства | Flash / RAM | Верхняя граница прошивки во Flash | Сектор настроек |
|---|---|---|---|---|
| `F401C` | `STM32F401xC` | 256 / 64 KiB | `0x08020000` (не включается) | сектор 5, последние 128 KiB |
| `F401E` | `STM32F401xE` | 512 / 96 KiB | `0x08060000` (не включается) | сектор 7, последние 128 KiB |
| `F411E` | `STM32F411xE` | 512 / 128 KiB | `0x08060000` (не включается) | сектор 7, последние 128 KiB |

Эти границы, стек 4 KiB и нулевой размер кучи соответствуют `cmsis/linker/*.icf`
и `hal/flash_store.c`, включая хранение во внутренней Flash при отсутствии
внешней SPI Flash. `F401E` поддерживается существующими ICF и заголовками
устройств/конфигурации; проекты IAR в репозитории непосредственно выбирают F401C
и F411E.

Результаты: `build/gcc/<CHIP>/<CONFIG>/teacup.{elf,hex,bin,map}` и
`build-options.txt` с данными о компиляторе и флагах сборки. `make clean` удаляет
только результаты сборки рабочей прошивки GCC. `TOOLCHAIN_PREFIX` и `PYTHON`
позволяют выбрать другие установленные инструменты; `EXTRA` передаёт дополнительные
флаги препроцессора. Изменения параметров или заголовков вызывают перекомпиляцию.
Не задавайте `TEACUP_RENODE_TEST` для реального оборудования.

`Release` использует `-Os`, `-O2` для существующего списка исходников с критичными
временными характеристиками и определяет `NDEBUG`; `Debug` использует `-Og`.
Обе конфигурации сохраняют отладочные символы, знаковый тип обычного `char` и
Cortex-M4F hard-float ABI. Стартовый код GCC копирует `.data` **и `.ramfunc`**,
обнуляет `.bss`, сохраняет `.noinit`, инициализирует массивы среды выполнения C
и вызывает рабочую функцию main из `app/mendel.c`. Куча для malloc намеренно
не выделяется.

Проверки сборки описаны в [TESTING.md](TESTING.md#проверки-сборки-рабочей-прошивки).
Линкер отклоняет
прошивку, заходящую в зарезервированную область настроек. Записывайте HEX или BIN
по адресу `0x08000000`; ни один из них не содержит данных для последнего сектора
настроек. **Полное стирание (mass erase) программатором уничтожает настройки**:
для их сохранения используйте запись с посекторным стиранием. Область RAM в map
показывает 100%, поскольку фиксированный стек расположен у верхней границы RAM;
для оценки свободного места смотрите статические данные и `__StackLimit`.

GitHub Actions собирает и проверяет все шесть вариантов рабочей прошивки в
Ubuntu и сохраняет артефакты ELF/HEX/BIN/map/параметров сборки. Проверки сборки
не заменяют проверку на плате: USB, временных характеристик движения,
безопасности нагрева и сохранения настроек через M500.

## Windows x64 MSI для Teacup Host

Готовый установщик: **Actions → Windows MSI → успешный запуск → Artifacts →
`TeacupHost-<версия>-win-x64-msi`**. Архив содержит
`TeacupHost-<версия>-win-x64.msi` и `.msi.sha256`.

MSI устанавливает только Windows-приложение из `host/`: .NET 8/WPF включён,
отдельная установка среды не требуется. Установка для всех пользователей
требует администратора. Можно выбрать папку (по умолчанию
`C:\Program Files\TeacupHost`); создаётся ярлык **Teacup Host** в меню «Пуск»
с иконкой из фактического EXE. Обновление сохраняет выбранную папку,
понижение версии блокируется. Восстановление и удаление не затрагивают
настройки `%AppData%\TeacupHost`. MSI не прошивает плату и не устанавливает
USB-драйверы. Перед обслуживанием закройте приложение.

Workflow работает на `windows-latest`, Release / `win-x64`, запускается для
PR и push в `main` и вручную. Версия по умолчанию `1.0.<номер запуска>`;
в ручном запуске доступен параметр `version`. Описание проверок установщика — в [TESTING.md](TESTING.md#проверки-msi).

Пакет не подписан; SHA-256 не заменяет подпись. Артефакт Actions не является
автоматическим GitHub Release. Self-contained .NET нужно
обновлять пересборкой и выпуском новой версии приложения.

Локальная сборка на Windows x64 с PowerShell 7 и .NET 8 SDK:

```powershell
pwsh -File installer/build-msi.ps1 -Version 1.0.0
```

Подробности, команды тихой установки и ограничения версий:
[installer/README.md](installer/README.md). WiX и UI-расширение закреплены
на версии **5.0.2**; исходный код приложения и схема настроек не меняются.

## Настройка проекта IAR

**Defined symbols** — ровно один символ выбора кристалла:

| Кристалл                     | Символ        | Startup                              | Линкер (опционально)                  |
|------------------------------|---------------|--------------------------------------|---------------------------------------|
| STM32F401CC (Black Pill 256K)| `STM32F401xC` | `cmsis/startup/startup_stm32f401xc.s`| `cmsis/linker/stm32f401xc_flash.icf`  |
| STM32F401CE (512K)           | `STM32F401xE` | `cmsis/startup/startup_stm32f401xe.s`| `cmsis/linker/stm32f401xe_flash.icf`  |
| STM32F411CE                  | `STM32F411xE` | `cmsis/startup/startup_stm32f411xe.s`| `cmsis/linker/stm32f411xe_flash.icf`  |

Файл платы выбирается автоматически по этому символу (`config/config.h`).
Больше ничего определять не нужно: `__ARM_STM32__`, `F_CPU`,
`USER_CONFIG` и прочие символы от старой сборки нужно **убрать**.

**Include paths** (относительно `$PROJ_DIR$`, если проект лежит в этом каталоге):

```
cmsis/core
cmsis/device
config
hal
core
display
motion
pff
src
```

**Файлы проекта** — все `*.c` из каталогов:
`app/` (`mendel.c`), `cmsis/` (`system_stm32f4xx.c`), `hal/`, `core/`,
`display/`, `motion/`, `pff/`, `src/`, плюс один startup-файл `.s`
из таблицы. Каталог `test/` в проект **не** добавлять.

Модули, выключенные в конфигурации (дисплей, SD, I2C, SPI), компилируются
в пустые объектные файлы, поэтому добавлять можно всё подряд.

**Прочие опции IAR:**

- Язык C, диалект C11 или C18 (по умолчанию). Используются анонимные
  struct/union из C11.
- Опцию General Options → Library Configuration → *Use CMSIS* лучше
  выключить: в проекте свой CMSIS 5.9 (`cmsis/core`). Если она включена,
  наши пути всё равно стоят раньше.
- FPU: VFPv4 single precision (Cortex-M4F).
- ICF из `cmsis/linker` — это файлы ST со стеком 4 КБ и нулевой кучей.
  Можно оставить и свои, но стек должен быть не меньше 2 КБ.

## Конфигурация Prusa i3 Steel

По умолчанию (`config/config.h`) собирается принтер Prusa i3 Steel на
Black Pill. Файл платы общий для F401 и F411, частота выбирается по
символу кристалла.

- `config/board.blackpill_p3steel.h` — распиновка (это предложение,
  подгоните под свою разводку), термисторы, нагреватели.
- `config/printer.p3steel.h` — механика, скорости, температуры и PID,
  перенесённые из Marlin.

Файлы `board.blackpill_stm32f401.h`, `board.blackpill_stm32f411.h` и
`printer.mendel.h` оставлены как общий пример.

### Распиновка P3 Steel (окончательная)

Распиновка рассчитана сразу на все запланированные дополнения, чтобы
больше не переставлять провода. Приоритеты: сначала всё для печати с
компьютера (USB, UART, моторы, нагрев, концевики, датчик уровня стола,
датчик филамента, блок питания), автономная печать — опция.

| Пин | Назначение | Пин | Назначение |
|-----|------------|-----|------------|
| PA0 | датчик филамента (параллельно кнопке KEY) | PB0 | стол, вкл/выкл |
| PA1 | термистор хотэнда | PB1 | термистор стола |
| PA2 | UART TX (хост) | PB2 | PS_ON (BOOT1) |
| PA3 | UART RX (хост) | PB3 | Y_MIN (EXTI3) |
| PA4 | CS SPI flash | PB4 | E_STEP, TIM3_CH1 |
| PA5 | SPI SCK | PB5 | E_DIR |
| PA6 | SPI MISO | PB6 | I2C1 SCL: дисплей, PCF8574 (опция) |
| PA7 | SPI MOSI | PB7 | I2C1 SDA: дисплей, PCF8574 (опция) |
| PA8 | X_STEP, TIM1_CH1 | PB8 | хотэнд, TIM10_CH1, 100 Гц |
| PA9 | X_DIR | PB9 | вентилятор обдува, TIM11_CH1, 500 Гц |
| PA10 | Y_DIR | PB10 | X_MIN (EXTI10) |
| PA11 / PA12 | USB | PB12 | Z_STEP (драйверы Z и Z2) |
| PA13 / PA14 | SWD | PB13 | Z_DIR (драйверы Z и Z2) |
| PA15 | Y_STEP, TIM2_CH1 | PB14 | EN всех драйверов |
| | | PB15 | Z_MIN / датчик уровня стола (EXTI15) |
| | | PC13 | серво BLTouch (на пине светодиод платы) |
| | | PC14 | CS SD-карты (`SD_CARD_SELECT_PIN`, опция) |
| | | PC15 | Z2_STEP (`Z_STEPPER_ALIGN`) или CS MAX31865 (`HOTEND_MAX31865`) |

**Что изменилось в проводке:**

- **Драйвер Z2** подключается параллельно драйверу Z: его STEP и DIR — на
  PB12 и PB13. Прошивка и раньше двигала Z и Z2 одинаково, освободились
  два пина. Если Z2 был инвертирован (`Z2_INVERT_DIR`), переверните
  разъём его мотора.
- **STEP осей X, Y и E** — на каналах таймеров TIM1, TIM2, TIM3, включён
  `STEP_TIMER_PULSES`. При старте выводится
  `echo:Step pulses: X TIM1 Y TIM2 Z gpio E TIM3`. Z остаётся на
  GPIO-импульсах: он шагает редко, только при смене слоя и Z-hop.
- **Хотэнд и вентилятор** остались на PB8 и PB9, но работают от TIM10 и
  TIM11 (в `DEFINE_HEATER` имена `PB_8_TIM10` и `PB_9_TIM11`). TIM1–TIM3
  заняты шагами, TIM5 задаёт время шагов. Частоты по-прежнему разные:
  100 и 500 Гц.
- **Стол** — PB0, PID с медленным программным ШИМ 2 Гц (`PB_0_GPIO`:
  таймер пина, TIM3, занят импульсами E).
- **Концевики** X, Y, Z — PB10, PB3, PB15. Эти пины допускают 5 В, линии
  EXTI 10, 3, 15 разные.

**Зарезервировано под будущие функции** (прошивка их пока не использует):

- **Датчик окончания филамента** — PA0, контакт на GND. Параллельно ему на
  плате стоит кнопка KEY: её нажатие имитирует срабатывание датчика.
  PA0 не допускает 5 В: датчик с выходом 5 В подключайте через делитель.
- **Датчик уровня стола** — сигнал на Z_MIN (PB15, допускает 5 В),
  заменяет концевик Z.
- **Серво BLTouch** — PC13. Свободных таймеров не осталось, импульсы
  будут программными (BLTouch к этому терпим). Светодиод платы на PC13
  будет мигать вместе с ними.
- **Дисплей** — I2C1 на PB6/PB7 (SSD1306 или HD44780 с платой PCF8574),
  см. «Дисплей, кнопки и меню».
- **Кнопки** — расширитель PCF8574 на той же шине I2C (адрес 0x20), P0…P3;
  P4, P5 свободны (энкодер, пищалка), P6, P7 — вентиляторы.
- **SD-карта** — SPI1 общий с SPI flash, CS на PC14 (`SD_CARD_SELECT_PIN`,
  см. «SD-карта на шине SPI flash»).
- **PC15** — резерв: отдельный STEP для Z2 для
  независимого выравнивания Z (`Z_STEPPER_ALIGN`, `G34`, см. ниже) или
  CS платы MAX31865 для PT100 (`HOTEND_MAX31865`).
- **PC14 и PC15** заняты кварцем 32,768 кГц. Прошивка его не использует;
  для SD-карты и резерва кварц нужно снять. Эти пины медленные (до
  2 МГц, 3 мА), но для CS, входов и сигнала серво этого достаточно.

Если какой-либо пин останется на PA11/PA12 (USB), сборка остановится с
`#error`.

**Перенесено из Marlin:**

- шаги 160 / 160 / 8000 / 1672 на мм;
- второй мотор Z на отдельном драйвере (теперь драйвер Z2 включён
  параллельно драйверу Z);
- инверсия E;
- концевики MIN, активный низкий уровень, внутренние подтяжки;
- программные границы 220 × 180 × 200 мм;
- рывки 20 / 0,4 / 5 мм/с;
- MINTEMP / MAXTEMP 5 / 275 °C для хотэнда и 5 / 150 °C для стола;
- PID хотэнда (стол теперь тоже на PID, bang-bang включается
  `BANG_BANG_BED`).

**Изменено относительно Marlin:**

- Максимальные скорости снижены до 150 / 150 / 4 / 25 мм/с: 500 мм/с
  недостижимы механически и по частоте шагов.
- Ускорение печати 1000 мм/с² вместо 50, ретракта 5000 мм/с², холостых
  перемещений 1000 мм/с².
- Защита от теплового разгона включена (в Marlin была выключена).

**Пересчёт PID из Marlin.** Коэффициенты хранятся в единицах Teacup:

```
P = Kp·256    I = Ki·64    D = Kd·128    I_LIMIT = 255·1024 / I
```

Сам PID считает во float и берёт из них Kp, Ki (в секунду) и Kd (в
секундах) Marlin, поэтому значения из Marlin и `M303` подходят напрямую
(подробнее в разделе «Температура: PID, обдув, стол»). Удобнее всего
задавать их командами `M301` / `M304` в единицах Marlin.

**Стол** работает на PID (`DEFAULT_BED_P/I/D`, `M304`) с медленным
программным ШИМ 2 Гц. Прежний режим bang-bang включается
`#define BANG_BANG_BED`: включение ниже цели − 2 °C, выключение выше
цели + 2 °C.

## Термисторы: уравнение Стейнхарта — Харта

Таблицы термисторов удалены. АЦП работает в 12-битном режиме с
усреднением 16 отсчётов, температура вычисляется по уравнению:

```
1/T = A + B·ln(R) + C·ln(R)³
```

Коэффициенты A, B, C рассчитываются при старте по трём точкам:

```
DEFINE_THERMISTOR(epcos100k, 4700.0, 25.0, 100000.0, 150.0, 1641.9, 250.0, 226.15)
DEFINE_TEMP_SENSOR(extruder, TT_THERMISTOR, PA_4, THERMISTOR_epcos100k)
```

Параметры: имя, подтяжка в омах (**к 3,3 В**), затем три пары
«температура °C / сопротивление Ом». Это та же модель, по которой
скрипт Marlin `createTemperatureLookupMarlin.py` строит таблицы; точки
выше соответствуют датчику Marlin типа 1 (EPCOS 100k).

Поведение при неисправности датчика:

- обрыв термистора даёт 0 °C → срабатывает MINTEMP;
- короткое замыкание даёт 1000 °C → срабатывает MAXTEMP.

AD595 пересчитан на 12 бит и опорное напряжение 3,3 В (измеряет до
330 °C).

## PT100 через MAX31865 (`HOTEND_MAX31865`)

Вместо термистора хотэнда можно подключить платиновый датчик PT100
(или PT1000) через плату MAX31865 (Adafruit и клоны). Он точен без
калибровки и работает выше 300 °C (цельнометаллические хотэнды, PEEK,
PC, нейлон), где термистор 100k уже врёт. Стол остаётся на термисторе
PB1, PA1 освобождается.

Включается в `board.blackpill_p3steel.h`:

```
#define HOTEND_MAX31865
#define MAX31865_CS_PIN          PC_15
#define MAX31865_WIRES           2        // 2, 3 или 4 провода
#define MAX31865_RREF            430.0    // опорный резистор платы, Ом
#define MAX31865_R0              100.0    // 100 = PT100, 1000 = PT1000
#define MAX31865_50HZ                     // фильтр сети 50 Гц (иначе 60 Гц)
```

**Подключение.** MAX31865 сидит на шине SPI1 вместе с SPI flash:

| MAX31865 | Black Pill |
|----------|------------|
| VIN | 3,3 В |
| GND | GND |
| CLK | PA5 |
| SDO | PA6 (MISO) |
| SDI | PA7 (MOSI) |
| CS | PC15 |

Все остальные пины заняты, поэтому CS — на PC15 (кварц 32,768 кГц на
PC14/PC15 снять). PC15 нужен и для Z2_STEP в `Z_STEPPER_ALIGN` — вместе
их не включить (ошибка компиляции); тогда CS можно перенести на PC14,
если нет SD-карты (`MAX31865_CS_PIN PC_14`).

- `MAX31865_WIRES` должен совпадать с перемычками на плате (см.
  описание своей платы). На Adafruit: 4 провода — как с завода;
  2 провода — замкнуть 2/3 Wire; 3 провода — замкнуть 2/3 Wire,
  перерезать дорожку 24 и замкнуть 3.
- `MAX31865_RREF` — опорный резистор платы: у Adafruit и большинства
  клонов 430 Ом для PT100 и 4300 Ом для PT1000. Он напечатан на
  резисторе (431 = 430 Ом); ошибка в нём даёт пропорциональную ошибку
  сопротивления.

**Как работает.** MAX31865 сам преобразует непрерывно (смещение и
автоматический режим включаются при старте, каждые ~20 мс), прошивка
читает регистр RTD раз в 100 мс — с частотой PID. Сопротивление
`R = код / 32768 · RREF` пересчитывается в температуру по уравнению
Каллендара — Ван Дюзена (IEC 60751, A = 3,9083·10⁻³, B = −5,775·10⁻⁷);
ниже 0 °C — полиномом, отрицательные температуры отображаются как 0.
Для PID значение идёт без округления до ¼ °C, как и у термисторов.

MAX31865 работает только в режимах SPI 1 и 3, а SPI flash и SD-карта — в
режиме 0. Поэтому `spi_mode()` переключает режим вокруг каждого обмена с
MAX31865 и сразу возвращает режим 0; скорость тоже выставляется перед
каждым обменом (100–400 кГц). Все устройства отпускают CS до вызова
`clock_poll()`, так что чтение датчика не пересекается с обменом flash.

**Неисправность.** Обрыв, короткое замыкание датчика или проводов
MAX31865 отмечает битом fault. Тогда показания не обновляются, fault
сбрасывается и чтение повторяется. Если при включённом нагревателе
показаний нет 4 с, защита останавливает принтер:
`Error:Temperature sensor timeout, system stopped!`. В отладочной
сборке (`DEBUG`) после `M111 S16` (флаг `DEBUG_PID`) каждая ошибка
выводится как `MAX31865 0 fault`.

После перехода на PT100 заново подберите PID (`M303`) и, если нужен
нагрев выше 275 °C, поднимите `HEATER_MAXTEMP` — хотэнд и
термобарьер должны это выдерживать.

## Выбор пинов в стиле Arduino

Пины задаются так же, как в ядре Arduino STM32, двумя способами: `PA_5`
или `PA5`. Например, `#define X_STEP_PIN PA_10`. Таблица пинов
`hal/pins_stm32f4.h` генерируется скриптом. Для каждого пина в ней указаны
порт, бит, канал АЦП, таймер ШИМ, канал таймера, AF и признак CHxN. Все
макросы `READ/WRITE/SET_OUTPUT` раскрываются на этапе компиляции в одну
запись в регистр (`GPIOx->BSRR`).

Проверки при компиляции:

- термистор или AD595 на пине без АЦП — ошибка компиляции;
- `F_CPU` выше допустимой для кристалла — ошибка компиляции.

Таймерные каналы для аппаратного ШИМ нагревателей (TIM5 занят степпером):

- TIM1: PA8 PA9 PA10 PA11, PB13 PB14 PB15 (CHxN)
- TIM2: PA0 PA1 PA2 PA3 PA5 PA15 PB3 PB10
- TIM3: PA6 PA7 PB0 PB1 PB4 PB5
- TIM4: PB6 PB7 PB8 PB9

АЦП: PA0–PA7, PB0, PB1, PC0–PC5.

## Тактирование

PLL настраивается из кварца платы (`HSE_CLOCK_HZ`, у WeAct 25 МГц).

| Кристалл | `F_CPU` по умолчанию | Допустимые значения        |
|----------|----------------------|----------------------------|
| F401     | 84 МГц               | 48 / 84 МГц                |
| F411     | 96 МГц               | 48 / 84 / 96 / 100 МГц     |

При частотах 48, 84 и 96 МГц получается ровно 48 МГц для USB. С `USB_CDC`
частота 100 МГц даёт `#error`: 48 МГц от неё не получить.

Если кварц не запустился, прошивка переходит на внутренний HSI 16 МГц с
той же `F_CPU` и после `start` сообщает `// clock: HSE crystal failed`.

## Безопасность

Все параметры задаются в разделе SAFETY файла `config/printer.mendel.h`.
Если в старом конфиге их нет, `config_wrapper.h` подставляет значения
Marlin, поэтому защита включена всегда.

Проверки выполняются каждые 250 мс для каждого датчика, к которому
привязан нагреватель (`core/thermal_protection.c`):

- **MAXTEMP** — проверяется всегда, даже при выключенном нагревателе.
  Ловит КЗ термистора и (поздно) пробитый MOSFET.
- **MINTEMP** — только при включённом нагревателе. Ловит обрыв термистора.
- **Heating failed** — после установки цели температура должна расти на
  `WATCH_TEMP_INCREASE` за каждые `WATCH_TEMP_PERIOD`, а у самой цели —
  дойти до неё за `THERMAL_PROTECTION_PERIOD`.
- **Thermal Runaway** — после выхода на цель температура не должна
  находиться ниже цели на `THERMAL_PROTECTION_HYSTERESIS` дольше чем
  `THERMAL_PROTECTION_PERIOD`.
- **Таймаут датчика** — нет валидных чтений `TEMP_SENSOR_TIMEOUT` секунд
  при включённом нагреве.
- **Ограничение цели** — M104/M140 не выше `MAXTEMP − OVERSHOOT`.
- **Нагреватель не выключается** (пробитый MOSFET, залипшее реле; в Marlin
  такой проверки нет). Пока выход нагревателя выключен (ШИМ 0), температура
  не должна вырасти больше чем на `THERMAL_PROTECTION_OFF_RISE` за
  `THERMAL_PROTECTION_OFF_PERIOD` секунд (для стола — `_BED_OFF_`).
  Первый период после выключения не оценивается: в это время температура
  ещё растёт по инерции. Проверка работает и при удержании цели: когда
  температура уходит выше цели, выход ПИД падает до 0. Сообщение:
  `Error:Heater off but temperature rising, system stopped! Heater_ID: n`.

Для MIN/MAXTEMP и проверки выключенного нагревателя нужно 3 плохих
чтения подряд (`TEMP_ERROR_READINGS`), чтобы одиночная помеха не
останавливала принтер. Для стола (датчик `bed` при заданном `HEATER_BED`)
действуют отдельные значения.

**Пороги проверки выключенного нагревателя** (по умолчанию):

| | Период | Допустимый рост | Скорость срабатывания |
|---|---|---|---|
| Хотэнд | 20 с | 20 °C | больше 1 °C/с |
| Стол | 60 с | 10 °C | больше 0,17 °C/с |

Хотэнд с пробитым MOSFET греется со скоростью 2–5 °C/с, стол 12 В —
0,3–0,5 °C/с. Сопло, опущенное на горячий стол, греется заметно медленнее
порога хотэнда. Если проверка всё же срабатывает ложно (мощный стол на
220 В, сопло прижато к нему), увеличьте `THERMAL_PROTECTION_OFF_RISE`.
Значение 0 отключает проверку.

Стол на полной мощности часто вообще не доходит до `BED_MAXTEMP`, поэтому
для него эта проверка — единственная защита от пробитого MOSFET. Сама
проверка только останавливает принтер. Пробитый MOSFET обесточит лишь
отключение блока питания, поэтому нужен `PS_ON_PIN` (см. ниже).

Старая проверка Teacup `HEATER_SANITY_CHECK` остаётся выключенной. Она
ничего не останавливает: только уменьшает выход и на каждом такте пишет
сообщение. Её задачи решают проверки выше.

**Аварийный останов `printer_kill()`** (`core/kill.c`):

- запрещает прерывания;
- переводит каналы ШИМ нагревателей в режим force inactive (действует
  сразу, без ожидания конца периода ШИМ);
- останавливает моторы и выключает блок питания (`PS_ON_PIN`,
  `PS_MOSFET_PIN`);
- выводит `Error:<причина> Heater_ID: n` и
  `Error:Printer halted. kill() called!` — OctoPrint и Pronterface по
  этим строкам останавливают печать.

В остановленном состоянии нагреватели держатся выключенными, watchdog
сбрасывается. `M999` перезагружает плату, иначе поможет только кнопка
сброса.

**Emergency parser** (`src/emergency_parser.c`) разбирает команды прямо
в прерываниях UART и USB (у каждого порта своё состояние), поэтому они срабатывают даже при занятой очереди и
во время G4 или M116:

| Команда | Действие |
|---------|----------|
| `M112`  | аварийный останов |
| `M108`  | отменить ожидание температуры |
| `M410`  | мгновенно остановить движение; позиция сохраняется, очередь сбрасывается |

**Watchdog** включён по умолчанию (`USE_WATCHDOG`, 500 мс). После
сброса по watchdog прошивка выводит `echo:Watchdog Reset`. После
HardFault плата перезагружается.

На плате обязательно нужен резистор, подтягивающий затвор MOSFET
нагревателя к земле: после сброса пины становятся входами.

### Управление блоком питания (`PS_ON_PIN`)

Пробитый MOSFET нагревателя программно не выключить: он проводит ток при
любом уровне на затворе. Обесточить нагреватель можно, только выключив
блок питания. Поэтому `printer_kill()` (все тепловые ошибки, `M112`)
выключает блок питания через `PS_ON_PIN`.

Схемы подключения:

| Опции | Уровень «включено» | Подключение |
|---|---|---|
| `PS_ON_PIN` + `PS_INVERT_ON` | высокий, выход всегда активен (3,3 В) | модуль реле или SSR в цепи 220 В блока 12 В; ATX через NPN-транзистор или оптопару (коллектор к PS_ON, эмиттер к GND) |
| `PS_ON_PIN` без `PS_INVERT_ON` | низкий; «выключено» — пин отпущен | PS_ON блока ATX (зелёный провод) напрямую, только на пин с допуском 5 В (FT) |
| `PS_MOSFET_PIN` | высокий | MOSFET в цепи 12 В |

**Конфигурация P3 Steel:** `PS_ON_PIN PB_2` с `PS_INVERT_ON`. На вход
модуля или транзистора поставьте резистор 10 кОм на землю: от сброса до
запуска прошивки пин висит в воздухе, и блок питания в это время должен
оставаться выключенным. PB2 — это ещё и BOOT1. С таким резистором вход в
загрузчик DFU (BOOT0 + reset) работает как обычно. Если подать на PB2 5 В
от ATX напрямую, BOOT0 + reset будет запускать прошивку из SRAM.

**Питание самой Black Pill** не должно идти от отключаемого блока: только
USB, дежурные 5 В ATX (5VSB) или отдельный источник 5 В. Иначе после
`printer_kill()` плата выключится вместе с блоком и не сможет сообщить об
ошибке.

**Когда блок включается и выключается:**

- Включается сам при первом нагреве или движении. `M80` включает его
  заранее. После включения прошивка ждёт 500 мс, пока блок выйдет на
  режим, поэтому первое движение после включения начинается с задержкой.
- Выключается при `printer_kill()`, `M81` и `M2`.
- С опцией `PS_AUTO_OFF` блок выключается ещё и после 30 с простоя (все
  нагреватели выключены, нет движений). Моторы при этом теряют
  удержание, даже если задано `M84 S0`.
- После `M999` и любого сброса блок остаётся выключенным, пока он не
  понадобится.

Раньше тот же 30-секундный таймер отключал драйверы моторов даже при
`M84 S0`. Теперь моторы отключаются только по своему таймеру
(`STEPPER_IDLE_TIMEOUT`, `M84 S`).

## Связь с хостом

Команды хоста проходят через очередь команд `src/gcode_queue.c`. Протокол
совместим с Marlin: OctoPrint, Pronterface, Repetier-Host и Cura работают
с прошивкой без дополнительной настройки. Параметры — в разделе HOST
COMMUNICATION файла `printer.mendel.h`.

### Порты: USB CDC и UART

Хост подключается двумя способами, оба работают одновременно:

- **USB CDC** (`USB_CDC` в файле платы, включено во всех файлах плат) —
  виртуальный COM-порт через разъём USB на Black Pill (PA11/PA12),
  основное подключение;
- **UART** (`SERIAL_UART`, по умолчанию USART2 на PA2/PA3) — через
  USB-UART адаптер, дополнительное подключение.

**Кто получает ответ.** Каждая строка G-кода помнит, из какого порта она
пришла. Ответы на команду (включая `ok`, `Error`, `Resend`) уходят только
в этот порт. У каждого порта свой приём строк и своя нумерация `N`,
поэтому, например, OctoPrint по USB и терминал по UART друг другу не
мешают. Во все порты уходят только сообщения вне команд: `start` после
сброса, ошибки нагрева и `kill`, печать с SPI flash / SD.

`M112`, `M108`, `M410` действуют из любого порта: `M109`, запущенный по
UART, можно отменить `M108` по USB. `M999` в остановленном состоянии
принимается из любого порта.

**Драйвер USB** (`hal/usb_cdc.c`) написан на регистрах OTG_FS, без
библиотеки ST. Класс CDC ACM:

- **Windows 10/11** ставит встроенный драйвер `usbser.sys` сам, порт
  появляется как COMx;
- **Linux** — `/dev/ttyACM0`, постоянное имя
  `/dev/serial/by-id/usb-Teacup_Teacup_3D_printer_<UID>-if00`.
  ModemManager порт не трогает: в дескрипторе нет протокола AT-команд.

Серийный номер USB — 96-битный уникальный ID чипа (24 шестнадцатеричные
цифры), поэтому у каждой платы своё постоянное имя и номер порта.
Скорость в настройках терминала ни на что не влияет.

Опции в файле платы:

| Опция | По умолчанию | Назначение |
|-------|--------------|------------|
| `USB_VID`, `USB_PID` | `0x0483`, `0x5740` | ST Virtual COM Port. Для раздачи прошивки другим людям нужна своя пара VID/PID |
| `USB_MANUFACTURER` | `"Teacup"` | строка производителя |
| `USB_PRODUCT` | `"Teacup 3D printer"` | название устройства |
| `USB_RX_BUFSIZE`, `USB_TX_BUFSIZE` | 256, 512 | буферы приёма и передачи, степени двойки |
| `USB_TX_TIMEOUT_MS` | 50 | сколько ждать хост при полном буфере передачи |

**Поведение:**

- **Приём без потерь.** Пока в буфере приёма нет места под пакет
  (64 байта), прошивка отвечает хосту NAK, и он ждёт. Строки не теряются
  при любой скорости отправки.
- **Принтер никогда не ждёт USB.** Если кабель вынут, порт на ПК закрыт
  (сигнал DTR снят) или хост перестал читать, вывод в USB
  отбрасывается (при закрытом порте — после заполнения буфера), а печать
  и UART продолжают работать. Ожидание при полном буфере — не больше
  `USB_TX_TIMEOUT_MS`, затем вывод отбрасывается, пока хост снова не
  начнёт читать.
- **VBUS не контролируется** (на Black Pill VBUS не заведён на PA9).
  Отключение кабеля ядро USB видит как suspend; при подключении ПК
  сбрасывает шину и перечисляет устройство заново.
- **После `M999` и сброса по watchdog** плата отключается от шины на
  несколько миллисекунд, и ПК перечисляет её заново. Pronterface и
  OctoPrint при этом теряют связь: нужно нажать «Connect» ещё раз.
  Сообщение `start` при загрузке уходит только в UART, так как USB в этот
  момент ещё не перечислен.
- **Кнопка Reset в Pronterface** (сброс по DTR) не перезагружает плату.
- **Тактирование.** USB требует точности ±0,25 %. Если кварц не
  запустился и прошивка работает от HSI (±1 %), при старте выводится
  `// USB clock from HSI, USB may not work`. Без PLL USB не включается
  (`// USB off, no 48 MHz clock`).

Отключить USB: закомментировать `#define USB_CDC` в файле платы. Старое
имя опции `USB_SERIAL` тоже включает USB CDC.

**Номера строк и контрольные суммы.** Строка вида `N<n> <команда>*<xor>`
принимается, если контрольная сумма верна и `n` = последний номер + 1.
`M110` задаёт номер строки. Строки без номера и без контрольной суммы
тоже принимаются. На ошибочную строку прошивка отвечает, как Marlin, и
хост пересылает её автоматически:

```
Error:checksum mismatch, Last Line: 41
Resend: 42
ok
```

Возможные ошибки: `checksum mismatch`, `Line Number is not Last Line
Number+1`, `No Checksum with line number`, `No Line Number with checksum`.

**Очередь команд.** До `CMD_BUFSIZE` строк (по умолчанию 8) принимаются
и проверяются заранее, в том числе пока выполняется долгая команда: M116,
G28, G4. Каждая выполненная строка получает ровно одно `ok`.

**ADVANCED_OK.** Ответ имеет вид `ok N<строка> P<свободно в очереди
движений> B<свободно в очереди команд>`. Хосты с поддержкой
ADVANCED_OK могут по нему слать строки заранее.

**Keepalive.** Пока одна команда выполняется долго, каждые
`HOST_KEEPALIVE_INTERVAL` секунд (по умолчанию 2) приходит
`echo:busy: processing`, чтобы хост не отвалился по таймауту.
`M113 S<сек>` меняет интервал, `M113 S0` выключает сообщения.

**Прочие сообщения:**

- `M105` отвечает одной строкой: `ok T:25.0/0.0 B:25.0/0.0 @:0 B@:0` (`@:` и
  `B@:` — выход нагревателей 0..255, как в Marlin).
- Неизвестная команда: `echo:Unknown command: "M9876"`.
- `M115` сообщает `Cap:AUTOREPORT_TEMP`, `Cap:EMERGENCY_PARSER` и
  `Cap:BUSY_PROTOCOL`.

### Потеря хоста (`HOST_WATCH`, `M86`)

При печати с компьютера принтер получает движения построчно. Если
программа на компьютере зависла, компьютер уснул или выдернут USB-кабель,
принтер стоит с горячим соплом в детали: пластик течёт, прожигает деталь,
филамент в термобарьере пригорает. Поэтому:

- слежение включается движением с E от хоста, пока у хотэнда есть
  целевая температура, и выключается, когда она сброшена (`M104 S0` в
  конце печати) или идёт печать с SD;
- хост потерян, если `M86 S` секунд (P3 Steel: 300) не пришло ни строки,
  пока принтер их ждал (команды не выполняются, очереди команд и движений
  пусты: долгий `M109`, `G4`, `M600` не в счёт), или USB-порт, с которого
  шли строки, закрыт или выдернут дольше 2 с;
- тогда после оставшихся в очереди движений: ретракт
  `HOST_LOST_RETRACT` (2 мм, если сопло горячее 180 °C), подъём Z на
  `HOST_LOST_Z_LIFT` (10 мм), парковка в `FILAMENT_CHANGE_PARK_X/Y` (если
  X и Y захоумлены), хотэнд на `M86 E` °C (0 — выключен). Стол сохраняет
  температуру.

```
M86 S300 E0     ; 300 с, хотэнд выключить
M86 S0          ; только отключение USB
M86             ; вывести
```

Продолжить такую печать нельзя. Тепловую защиту это не заменяет, она
работает всегда. **Пауза в хосте** (OctoPrint «Pause») дольше `M86 S`
тоже сработает — задайте время больше обычной паузы. `M500` сохраняет.

## Команды, совместимые с Marlin

| Команда | Действие |
|---------|----------|
| `M109 S<t>` / `M109 R<t>` | Нагреть экструдер и ждать. С `S` ждёт только нагрева, с `R` — и нагрева, и остывания. Ожидание закончено, когда температура продержалась в пределах `TEMP_HYSTERESIS` в течение `TEMP_RESIDENCY_TIME`. `M108` прерывает ожидание. |
| `M190 S<t>` / `M190 R<t>` | То же для стола (нужен `HEATER_BED`). |
| `M106 S<0..255>` | Вентилятор обдува, с kick-start и минимальным ШИМ (`FAN_KICKSTART_TIME`, `FAN_MIN_PWM`). `P<n>` — другой нагреватель/выход, без этих поправок. |
| `M107` | Выключить вентилятор, то же что `M106 S0`. |
| `G2` / `G3` | Дуга по / против часовой стрелки в плоскости XY (подробнее ниже). |
| `M80` | Включить блок питания и дождаться его выхода на режим (`PS_ON_PIN`, `PS_MOSFET_PIN`). |
| `M81` | Дождаться конца движений, выключить нагреватели и вентилятор, отключить моторы и блок питания. |
| `M17` | Включить драйверы моторов. |
| `M18`, `M84` | Выключить драйверы моторов. **Нагреватели не трогает** (в старом Teacup `M84` был синонимом `M2`). |
| `M84 S<сек>` | Задать тайм-аут простоя (по умолчанию `STEPPER_IDLE_TIMEOUT` = 120 с, `S0` — никогда). Во время ожидания температуры моторы не отключаются. |
| `M114` | Позиция в формате Marlin: `X:10.000 Y:0.000 Z:0.000 E:0.000 Count X:400 Y:0 Z:0`. |
| `M117 <текст>` | Сообщение на дисплей (последняя строка), до 31 символа. Текст не разбирается как G-код. |
| `M73 P<%> R<мин>` | Прогресс печати. Без параметров — вывести текущее значение. |
| `M400` | Дождаться окончания всех движений. |
| `M206 X Y Z` | Смещения дома (подробнее ниже). |
| `M428` | Задать смещения так, чтобы текущая позиция стала домом. |
| `M300 S<Гц> P<мс>` | Звук на `BEEPER_PIN` (пассивный или `BEEPER_ACTIVE`), не длиннее 5 с. Без пищалки команда просто ждёт. |
| `M27` | Статус печати с SD: `SD printing byte n/m`. |
| `M26 S<байт>` | Перейти к позиции в файле на SD. |

**Дуги G2/G3.** Формат как в Marlin:

- `G2 X Y I J` — центр задан смещением `I`, `J` от начальной точки (всегда
  относительным, даже в `G90`). Если начальная точка совпадает с конечной,
  получается полная окружность.
- `G2 X Y R` — центр задан радиусом. При отрицательном `R` строится дуга
  длиннее 180°. Полную окружность через `R` задать нельзя.
- `Z` — винтовая линия: Z меняется равномерно вдоль дуги. `E`
  распределяется по длине дуги в абсолютном и относительном режиме.
- `P<n>` — добавить n полных оборотов.
- `F`, `G90`/`G91`, `M82`/`M83`, `G20`, программные ограничения, `M220`
  и `M221` работают как для `G1`.

Дуга разбивается на отрезки. Длина отрезка выбирается так, чтобы хорда
отклонялась от дуги не больше `ARC_TOLERANCE` (0,01 мм), в пределах
`ARC_SEGMENT_MIN`…`ARC_SEGMENT_MAX` (0,1…1 мм). Например, при радиусе 5 мм
отрезок около 0,63 мм, при радиусе 0,5 мм — 0,2 мм. Точки считаются от
центра для каждого отрезка, а последний отрезок приходит точно в заданную
конечную точку, поэтому ошибка округления не накапливается.

В относительном режиме E (`M83`) дробная часть шага переносится из
движения в движение, в том числе между отрезками дуги. Раньше каждое
движение округлялось отдельно, и на длинной серии коротких движений
терялись шаги (на тестовой дуге — 835 шагов вместо 836).

Если нет ни `I`/`J`, ни `R`, или радиус нулевой, прошивка отвечает
`echo:G2/G3 bad parameters` и не двигается. `M410` во время длинной дуги
останавливает её, оставшиеся отрезки в очередь не попадают.
`NO_ARC_SUPPORT` отключает дуги: они займут около 6 КБ flash вместе с
`sinf`/`cosf`/`atan2f`.

**Смещения дома (`M206`).** Смещение сдвигает систему координат: после
хоуминга ось показывает позицию дома плюс смещение. Мягкие ограничения
(`X_MIN` и т.п.) сдвигаются вместе с ним. Без параметров `M206` выводит
текущие смещения. Смещения сохраняются `M500`.

## Датчик филамента, смена филамента, babystepping, BLTouch и сетка стола

### Датчик филамента (`FILAMENT_RUNOUT_PIN`, `M412`)

Датчик подключается к PA0 (контакт на GND, внутренняя подтяжка
включена). `FILAMENT_RUNOUT_STATE` — уровень при отсутствии филамента,
для контакта на GND это 0. Кнопка KEY на плате стоит параллельно PA0:
её нажатие во время печати работает как ручная пауза. Без датчика
подтяжка держит вход в состоянии «филамент есть».

Пауза начинается не в момент срабатывания датчика, а после того, как в
хотэнд подано ещё `FILAMENT_RUNOUT_DISTANCE` мм (25 мм, филамент между
датчиком и соплом). Шаги E считаются при старте каждого движения, поэтому
в простое без филамента пауза не срабатывает. Паузу запускает главный
цикл между двумя командами (как Marlin, через ту же процедуру, что и
`M600`); движения, уже стоящие в очереди, сначала доезжают.

| Команда | Действие |
|---------|----------|
| `M412` | Состояние: включено ли, расстояние, датчик. |
| `M412 S0` / `S1` | Выключить / включить обнаружение. |
| `M412 D<мм>` | Расстояние после срабатывания. |
| `M412 R` | Забыть обнаруженное окончание. |
| `M119` | Среди концевиков строка `filament:open` / `filament:triggered` (нет филамента). |

`S` и `D` сохраняются `M500`.

### Смена филамента (`M600`)

`M600 [E<ретракт>] [Z<подъём>] [X<x>] [Y<y>] [U<выгрузка>] [L<загрузка>]`,
по умолчанию значения `FILAMENT_CHANGE_*` из конфигурации принтера:

1. дождаться конца движений, запомнить позицию (X, Y, Z, E, F);
2. ретракт 2 мм, подъём Z на 20 мм (не выше `Z_MAX`), парковка в
   X10 Y170 — только если X и Y захоумлены;
3. выгрузка 50 мм;
4. ожидание пользователя. Хост получает `echo:busy: paused for user`
   каждые 2 с (OctoPrint и Pronterface не рвут связь) и запрос для
   OctoPrint (`//action:prompt_begin Insert filament`, кнопка Continue).
   Продолжить: `M108` (Pronterface) или кнопка Continue в OctoPrint
   (`M876 S0`). Обе команды обрабатывает emergency parser, поэтому они
   действуют и при полной очереди команд. Через
   `FILAMENT_CHANGE_NOZZLE_TIMEOUT` (300 с) нагреватель хотэнда
   выключается, перед загрузкой он снова нагревается;
5. загрузка и прочистка 40 мм на 3 мм/с, ретракт;
6. возврат по X/Y, опускание Z, возврат ретракта.

Все движения E при смене выполняются вне системы координат G-кода. После
продолжения логическая позиция, включая E, та же, что и до паузы, в
абсолютном и в относительном режиме E. Если хотэнд холоднее
`FILAMENT_CHANGE_MIN_TEMP` (170 °C), филамент не двигается, остальное
выполняется. Во время паузы моторы не отключаются по тайм-ауту, а блок
питания не выключается по `PS_AUTO_OFF`.

`M115` сообщает `Cap:HOST_ACTION_COMMANDS:1`, `Cap:PROMPT_SUPPORT:1`,
`Cap:FILAMENT_RUNOUT:1`. При окончании филамента дополнительно выводится
`//action:out_of_filament T0`.

### Babystepping (`BABYSTEPPING`, `M290`)

`M290 Z<мм>` сразу сдвигает сопло по Z, в том числе посреди движения,
например при подстройке первого слоя. Логические координаты не меняются
(`M114` показывает то же), поэтому печать продолжается с новым зазором.
Сдвиги суммируются в «Z offset» (как Live adjust Z у Prusa), ограниченный
`BABYSTEP_LIMIT` (±2 мм). Он сохраняется `M500` и действует после
следующего хоуминга. `M290` без параметров выводит текущее смещение.

Шаги делает третий канал сравнения таймера шагов TIM5 в том же
прерывании, что и шаги движений, со скоростью `BABYSTEP_FEEDRATE`
(1 мм/с). Если в этот момент идёт Z-импульс движения, babystep ждёт.
DIR переключается на время шага с паузой 1 мкс до и после импульса
(DRV8825 требует 650 нс), затем восстанавливается. Шаг движения
задерживается не больше чем на ~4 мкс. `M400`, хоуминг и пробинг ждут
окончания babystep'ов.

### Подъём Z перед хоумингом (`Z_HOMING_HEIGHT`)

Перед хоумингом X или Y (`G28`, `G28 X`, `G28 Y`) Z поднимается до
`Z_HOMING_HEIGHT` (P3 Steel: 5 мм), как в Marlin. Сопло и выдвинутый
щуп BLTouch не цепляют стол и прижимы. Z только поднимается, вниз не
идёт. Пока Z не захоумлен, текущий Z считается верным (после включения
это 0), поэтому повторный `G28 X` второй раз не поднимает. `0` —
выключено. `G28 Z` отдельно (без X/Y) ничего не поднимает: с концевиком
Z это не нужно, с зондом подъём делает сам хоуминг зондом.

### BLTouch (`BLTOUCH`)

Включается в файле платы (`#define BLTOUCH`): сигнал BLTouch (белый) — на
PB15 = `Z_MIN_PIN` (активный высокий, `Z_INVERT_MIN` для него снимается
автоматически), серво-вход (оранжевый) — на PC13, питание 5 В. У PC13
нет канала таймера, поэтому импульсы 50 Гц формирует TIM9 по
прерываниям: фронт по переполнению, спад по сравнению, джиттер —
единицы мкс. Светодиод платы на PC13 при этом мигает.

| Команда | Действие |
|---------|----------|
| `G28` / `G28 Z` | Z хоумится зондом (безопасный Z-хоуминг): если X или Y ещё не захоумлены, `G28 Z` сначала хоумит их; сопло поднимается на `Z_PROBE_CLEARANCE`, затем зонд ставится в центр стола (или в `Z_SAFE_HOMING_X/Y`). |
| `G30 [X Y]` | Замер в одной точке (положение зонда). Ответ `Bed X: … Y: … Z: …` — высота стола. |
| `G29` | Сетка `GRID_POINTS_X` × `GRID_POINTS_Y` по достижимой зондом области стола минус `MESH_INSET`, змейкой. Затем выравнивание включается и выводится сетка. Нужен хоуминг XYZ. |
| `M851 X Y Z` | Смещение зонда от сопла, мм. Z отрицательный: минус высота сопла над столом в момент срабатывания. |
| `M401` / `M402` | Выдвинуть / убрать щуп (индукционный датчик: только проверка, см. ниже). |
| `M280 P0 S<угол>` | Команда серво: 10 — выдвинуть, 90 — убрать, 160 — сброс аварии, 120 — самотест. |

Каждая точка меряется дважды: быстро (4 мм/с), затем после подъёма на
`Z_PROBE_RETRACT` медленно (1 мм/с); используется медленный замер.
Точка срабатывания берётся из числа шагов в момент фронта сигнала
(прерывание EXTI), поэтому перебег при торможении на результат не
влияет. Если зонд не сработал до `Z_PROBE_LOW_POINT` или не
выдвигается, выводится `Error:…`, а `G29` не включает выравнивание.

**Настройка смещения Z:** `M851 Z-5`, `G28`, опускать сопло `G1 Z…` до
касания листа бумаги, прочитать Z (`M114`), например 3.40. Тогда смещение
3.40 − 5 = −1.60: `M851 Z-1.60`, `M500`. Смещения X/Y зонда измерьте
линейкой. Тонкая подстройка при печати — `M290`.

### Индукционный датчик (`INDUCTIVE_PROBE`)

Вместо BLTouch в файле платы можно выбрать индукционный (или ёмкостный)
датчик приближения — как PINDA у Prusa или LJ12A3-4-Z:
`#define INDUCTIVE_PROBE` (оба сразу нельзя — `#error`). Серво нет,
выдвигать нечего: датчик срабатывает, подойдя к металлическому столу
(стальной лист, алюминий; через стекло не работает). Все команды те же:
`G28 Z` зондом, `G29`, `G30`, `G34`, `M851`; `M401` только проверяет, что
датчик ещё не сработал (иначе `Error:Probe triggered before probing`,
замер не начинается), `M402` ничего не делает, `M280` нет.

**Подключение.** Сигнал — на PB15 = `Z_MIN_PIN` (допускает 5 В),
внутренняя подтяжка включена (`USE_INTERNAL_PULLUPS`). Берите датчик типа
**NPN** (открытый коллектор, замыкает сигнал на GND у металла): тогда его
можно питать от 6–36 В, на пин приходят только подтяжка и GND.

| Тип датчика | Настройка |
|-------------|-----------|
| NPN NO (нормально открытый, самый частый) | по умолчанию, активный низкий |
| NPN NC | `#define INDUCTIVE_PROBE_ACTIVE_HIGH` |
| PNP | через делитель или оптопару до 3,3 В, затем по уровню |

PNP-выход, питающийся от 12 В, напрямую к пину не подключайте. NPN NO
без питания читается как «сработал» — `M401`/замер это заметит.

**Смещение Z** индукционного датчика — минус его дистанция срабатывания
над столом, обычно −1…−4 мм; настраивается так же, как выше. Дистанция
зависит от температуры датчика и стола: меряйте смещение и снимайте
сетку при рабочих температурах, со столом нагретым.

Попутно исправлено: `#ifndef BLTOUCH` для инверсии Z_MIN стоял в файле
платы выше строки `#define BLTOUCH`, поэтому BLTouch, включённый в самом
файле (а не через `-DBLTOUCH`), читался инвертированным. Теперь
полярность зонда выставляет `config_wrapper.h`, где все опции уже
известны: BLTouch — активный высокий, индукционный — по
`INDUCTIVE_PROBE_ACTIVE_HIGH`, без зонда — `Z_INVERT_MIN` концевика.

### Сетка стола (`BED_LEVELING`, `M420`, `M421`)

Мотор Z стоит в «логическом Z + коррекция», где коррекция = высота сетки
в точке (билинейная интерполяция, за краями сетки — значение края) ×
множитель затухания + Z offset (`M290`). Множитель затухания линейно
падает от 1 на Z = 0 до 0 на высоте `LEVELING_FADE_HEIGHT` (10 мм), выше
сопло идёт ровно по логическому Z. Движения режутся на границах ячеек
сетки, поэтому сопло повторяет поверхность и между узлами.

Когда коррекция меняется без движения (включение/выключение, новая
сетка, высота затухания, хоуминг, пробинг), моторы не двигаются. Вместо
этого пересчитывается логический Z, как в Marlin: после `M420 S0` в
`M114` виден Z с учётом прежней коррекции. Хоуминг и пробинг идут в
координатах моторов, без коррекции.

| Команда | Действие |
|---------|----------|
| `M420 S1` / `S0` | Выравнивание вкл/выкл (нужна сетка). |
| `M420 Z<мм>` | Высота затухания, `Z0` — без затухания. |
| `M420` (или `M420 V`) | Состояние и сетка. |
| `M421 I<i> J<j> Z<мм>` | Задать узел сетки вручную. Если сетки ещё нет, создаётся пустая `GRID_POINTS_X` × `GRID_POINTS_Y` по столу минус `MESH_INSET`. Так сетку можно измерить и без зонда. |

`M500` сохраняет сетку, её геометрию, состояние и высоту затухания;
после старта сетка сразу действует. `M503` выводит узлы строками
`M421 I J Z`.

### Выравнивание Z и Z2 (`Z_STEPPER_ALIGN`, `G34`)

Два мотора Z на двух винтах могут разойтись: винт провернули рукой при
выключенных моторах, мотор пропустил шаги. Тогда портал X стоит наклонно,
и первый слой с одной стороны толще. `G34` (как `Z_STEPPER_AUTO_ALIGN` в
Marlin) выравнивает портал зондом.

**Подключение.** STEP драйвера Z2 переносится с PB12 на PC15 (кварц
32,768 кГц на PC14/PC15 снять), DIR остаётся параллельно на PB13. В
`board.blackpill_p3steel.h` — `#define Z_STEPPER_ALIGN` (нужен и зонд:
`BLTOUCH` или `INDUCTIVE_PROBE`). Z и Z2 по-прежнему шагают вместе (оба пина на GPIO-импульсах),
раздельно — только во время `G34`.

**Как работает.**

1. Зонд меряет стол в двух точках, `Z_STEPPER_ALIGN_X1` и `X2` (у левого
   и правого края, на высоте `Z_STEPPER_ALIGN_Y`).
2. Через эти точки проводится прямая и продолжается до винтов
   (`Z_STEPPER_X1`, `Z_STEPPER_X2` — X винтов в тех же координатах, они
   за пределами стола; измерьте их). Где стол «выше» — там портал ниже.
3. Более низкий винт поднимается один на разницу. Только вверх, сопло в
   стол не упирается.
4. Повтор, пока точки не совпадут в пределах `Z_STEPPER_ALIGN_ACC`
   (0,02 мм), но не больше `Z_STEPPER_ALIGN_ITERATIONS` раз. Если
   разница не уменьшается, `G34` останавливается (проверьте X винтов);
   больше `Z_STEPPER_ALIGN_MAX` (5 мм) не исправляет.
5. Z хоумится зондом заново.

```
G28
G34            ; или G34 I8 T0.01: число итераций и точность, мм
G29            ; сетку снять заново, она мерилась при старом наклоне
M500
```

## Настройки во время работы и их сохранение

Эти команды меняют настройки без перепрошивки. Единицы — как в Marlin.
Без параметров команда выводит текущие значения.

| Команда | Что задаёт |
|---------|------------|
| `M92 X Y Z E` | Шагов на мм. Текущая позиция сохраняется. |
| `M201 X Y Z E` | Максимальное ускорение по оси, мм/с². |
| `M203 X Y Z E` | Максимальная скорость по оси, мм/с. |
| `M204 P R T` | Ускорение печати (`P`), ретракта (`R`), холостых перемещений (`T`), мм/с². `S` задаёт `P` и `T`, как в Marlin. |
| `M205 X Y Z E` | Рывок, мм/с. |
| `M900 K` | Linear advance, K в секундах (единицы Marlin), 0 — выключено. Только со сборкой `LINEAR_ADVANCE`. |
| `M593 X Y F D T S` | Input shaping X/Y: частота `F` (Гц, 0 — выкл.), демпфирование `D`, тип `T` (0 — ZV, 1 — MZV); S-кривая `S` (мс). Только со сборкой `INPUT_SHAPING`. |
| `M207 S F Z`, `M208 S F` | Прошивочный ретракт (`G10`/`G11`), только со сборкой `FIRMWARE_RETRACT`. |
| `M31`, `M75`–`M78` | Таймер и статистика печати (см. ниже). |
| `M997` | Перезагрузка в загрузчик USB DFU для обновления прошивки. |
| `M86 S E` | Потеря хоста: тайм-аут (с) и температура хотэнда, только со сборкой `HOST_WATCH`. |
| `M413 S` | Запись для восстановления после пропадания питания, только с `POWER_LOSS_RECOVERY`. |
| `M852 I` | Перекос XY (тангенс), только со сборкой `SKEW_CORRECTION`. |
| `M425 X Y Z F S` | Люфт осей (мм), доля компенсации и сглаживание (мм), только со сборкой `BACKLASH_COMPENSATION`. |
| `M218 T1 X Y Z` | Смещение сопла T1, только с `EXTRUDERS 2`. |
| `M205 J B` | Junction deviation (мм) и минимальное время сегмента (мкс). |
| `M200 D S L` | Диаметр филамента, объёмный E, предел мм³/с. |
| `M913` | Гибридный порог TMC, мм/с. |
| `M306` | Модель хотэнда (`HOTEND_MPC`). |
| `M423` | Скручивание оси X (с зондом). |
| `M906`, `M569` | Ток и stealthChop драйверов TMC, только с `TMC_UART`. |
| `M301 P I D F` | PID хотэнда (Kp, Ki, Kd в единицах Marlin), `F` — упреждение на обдув (см. ниже). |
| `M304 P I D` | PID стола. |
| `M500` | Сохранить во Flash. |
| `M501` | Загрузить из Flash. |
| `M502` | Вернуть значения из конфигурации. |
| `M503` | Вывести все настройки в формате Marlin. |

**Ускорение движения** выбирается, как в Marlin:

- только E (ретракт и обратная подача) — `M204 R`;
- без E (холостые перемещения, хоуминг) — `M204 T`;
- остальные (печать) — `M204 P`.

Ускорение действует вдоль пути, по реальному вектору движения. Каждая ось
получает свою долю: ускорение × (путь оси / длина движения). Если доля
какой-то оси больше её `M201`, ускорение движения уменьшается. Поэтому
движения только по Z идут с ускорением из `M201 Z`, а диагональ в XY
разгоняется с тем же ускорением, что и движение вдоль оси. Раньше рампа
считалась по самой быстрой оси, и диагональ разгонялась в √2 раз сильнее
заданного. Движения, уже стоящие в очереди, сохраняют своё ускорение.

**Что сохраняет `M500`:** шаги, скорости, ускорения, рывки, K linear advance, input shaping и S-кривую, смещения
дома (`M206`), PID всех нагревателей и упреждение на обдув (`M301 F`),
перекос XY (`M852`), люфт X/Y/Z и сглаживание (`M425`), ретракт (`M207`, `M208`),
смещение T1 (`M218`), ток и режимы драйверов TMC (`M906`, `M569`, `M913`),
junction deviation и замедление (`M205 J B`), объёмный расход (`M200`),
модель хотэнда (`M306`), перекос XZ/YZ (`M852 J K`), скручивание X (`M423`),
тайм-аут хоста (`M86`), `M413`, тайм-аут моторов (`M84 S`),
Z offset (`M290`), смещение зонда (`M851`), датчик филамента (`M412`),
сетку стола и её состояние (`G29`, `M420`, `M421`). Набор полей не
зависит от включённых опций, поэтому сохранённая запись переживает смену
конфигурации. Записи прежних форматов (без новых полей, например без
`M204 R`/`T`) тоже читаются: при загрузке выводится `old format`, новые
поля остаются по умолчанию.
При старте сохранённые значения загружаются автоматически.

**Где хранятся настройки.** В последнем секторе Flash (128 КБ):

| Кристалл | Адрес |
|----------|-------|
| F401CC | `0x08020000` |
| F401CE, F411CE | `0x08060000` |

Записи добавляются друг за другом, каждая с CRC32. Сектор стирается
только когда заполнится, поэтому его хватает на сотни сохранений. Если
питание пропадёт во время записи, при следующем старте загрузится
предыдущая целая запись.

**Ограничение `M500`.** Стирание сектора длится 1–2 с. Всё это время
прерывания запрещены, а ядро стоит (Flash во время стирания нельзя
читать). Поэтому `M500` сначала ждёт окончания всех движений; во время
печати его не вызывайте.

**Настройка IAR для хранения настроек:**

- Сектор с настройками не должен попадать в область кода. В
  `cmsis/linker/*.icf` конец ROM уже уменьшен: `0x0801FFFF` для F401CC,
  `0x0805FFFF` для F401CE/F411CE. Если используете свой ICF, сделайте
  так же.
- Функции стирания и записи помечены `__ramfunc` и выполняются из ОЗУ.
  Для этого в ICF должна быть строка `initialize by copy { readwrite };`
  (в шаблонах ST она есть).

## Автоподбор PID (`M303`)

```
M303 E0 S200 C8 U1      ; E0 хотэнд, E-1 стол; S — температура; C — циклы (3..20)
```

Алгоритм тот же, что в Marlin: релейные колебания вокруг заданной
температуры, затем расчёт по Зиглеру — Николсу.

- Результат выводится строками `#define DEFAULT_Kp …`, как в Marlin, и
  дополнительно строкой `echo:Teacup: DEFAULT_P …` в единицах Teacup —
  её можно вставить прямо в конфигурацию принтера.
- `U1` сразу применяет результат, `M500` его сохраняет.
- Тепловая защита во время подбора остаётся включённой.
- `M108` прерывает подбор.

## Температура: PID, обдув, стол

**PID на float, 10 Гц.** Регулятор каждого нагревателя считается раз в
100 мс (раньше 250 мс) во float на FPU, по температуре с полным
разрешением термистора (Стейнхарт — Харт до округления до ¼ °C).
Шаг времени измеряется. Устроен как в Marlin:

```
out = Kp·e + ∫Ki·e dt + D + упреждение     (0..255)
```

- **D по измерению, а не по ошибке**: `D = −Kd·dT/dt`, через фильтр
  нижних частот (`PID_D_FILTER` = 2 с, для стола `PID_D_FILTER_BED` =
  5 с). Смена цели не даёт броска, шум АЦП на 10 Гц не раскачивает выход.
- **Интеграл** ограничен `I_LIMIT` (`M133`) и не растёт, пока выход в
  насыщении (anti-windup).
- **`PID_FUNCTIONAL_RANGE`** (10 °C): дальше от цели — полная мощность или
  выключено, интеграл сбрасывается. Нет перегрева после разогрева.
- Тепловая защита по-прежнему проверяется раз в 250 мс.

**Упреждение на обдув (`M301 F`, как `PID_FAN_SCALING` в Marlin).** Когда
после первых слоёв включается обдув, хотэнд без компенсации проседает на
3–5 °C: PID замечает охлаждение только по падению температуры. С `F`
нагреватель получает прибавку сразу вместе с вентилятором:

```
прибавка = F · S / 255      (F — отсчёты ШИМ 0..255 при M106 S255)
```

Как подобрать `F`: держать температуру печати, записать средний ШИМ
хотэнда (`M105`, поле `@:`) с выключенным обдувом и при `M106 S255`;
разница и есть `F`. `M301 F<n>`, затем `M500`. По умолчанию
`DEFAULT_PID_FAN_FF` = 0 (выключено). В отличие от Marlin, `F` —
прибавка при полном обдуве, а не коэффициент на скорость вентилятора.

**Kick-start и минимальный ШИМ обдува.** Вентилятор, запущенный из
остановки на малых оборотах (`M106 S40`), может не стронуться. Поэтому:

- `FAN_KICKSTART_TIME` (P3 Steel: 200 мс) — из остановки вентилятор
  сначала получает полную мощность, затем заданную;
- `FAN_MIN_PWM` (P3 Steel: 40) — `M106 S1..255` пересчитывается в
  ШИМ `40..255`, на малых оборотах вентилятор не встаёт. `S0` — выключен.

Это касается только вентилятора обдува (`HEATER_FAN`). `M106 P<n>` на
другие выходы пишет значение как есть.

**PID стола с медленным программным ШИМ.** На P3 Steel стол на PB0, а
таймер этого пина (TIM3) занят импульсами E. Поэтому в `DEFINE_HEATER()`
стол задан как `PB_0_GPIO` (тот же пин без таймера) с `pwm` = 2:

- `pwm` 2..10 на пине без таймера — медленный программный ШИМ этой
  частоты: период 500 мс при 2 Гц, скважность с шагом 10 мс, остаток
  переносится в следующий период, так что средняя мощность точная;
- не больше 4 переключений в секунду: MOSFET и реле не греются, нагрузка
  на блок питания ровная;
- `pwm` 1 — как раньше, сигма-дельта каждые 10 мс; больше 10 на пине без
  таймера — тоже сигма-дельта.

Стол держит около ±0,3 °C вместо ±2 °C у bang-bang: нет периодического
«дыхания» стола по Z (тепловое расширение) и бросков тока на блок
питания. Значения по умолчанию (`DEFAULT_BED_P/I/D` = Kp 70, Ki 1,5,
Kd 800) — стартовые для стола MK2a/MK2B 12 В; подберите свои:

```
M303 E-1 S60 C8 U1
M500
```

Прежнее поведение возвращается `#define BANG_BANG_BED` в
`printer.p3steel.h`; медленный ШИМ ему не мешает (255 — включено весь
период, 0 — выключено).

## Вентилятор хотэнда и вентилятор контроллера

- **Хотэнд** (как `E0_AUTO_FAN` в Marlin): включён, пока хотэнд не
  холоднее `HOTEND_FAN_TEMP` (50 °C), в том числе после печати, пока не
  остынет; гистерезис 1 °C. Без обдува радиатора тепло поднимается по
  термобарьеру, и филамент застревает — пробка.
- **Контроллер** (как `CONTROLLER_FAN` в Marlin): включён, пока драйверы
  моторов включены, принтер движется или горит нагреватель, и ещё
  `CONTROLLER_FAN_IDLE` секунд (60) после.
- При аварийной остановке (`kill`) вентилятор хотэнда на пине МК
  включается; выход расширителя сохраняет состояние (включён, пока
  хотэнд горячий).

**Подключение на P3 Steel.** Свободных пинов МК не осталось, поэтому оба
вентилятора — на расширителе PCF8574 (I2C1, PB6/PB7, адрес 0x20),
выходы P6 и P7. Выход PCF8574 в «1» — только слабая подтяжка, поэтому
каждый вентилятор включается через модуль MOSFET с подтяжкой 10 кОм к
5 В на входе («1» — включён). P0…P3 — кнопки меню (см. «Дисплей, кнопки
и меню»), P4, P5 свободны. Без расширителя ничего не происходит (запись не
подтверждается), вентиляторы, подключённые напрямую к 12 В, работают
как раньше. Вместо расширителя можно задать пин МК: `HOTEND_FAN_PIN` /
`CONTROLLER_FAN_PIN` (активный высокий, `*_FAN_INVERT` — активный низкий).

Шина I2C общая с дисплеем: драйвер теперь поддерживает несколько адресов
(у каждой передачи свой адрес), расширитель ждёт, пока дисплей закончит
свою передачу.

## Дисплей, кнопки и меню (`DISPLAY_MENU`)

Дисплей и кнопки подключаются к шине I2C1 (PB6/PB7), свободных пинов МК
для них не нужно. По умолчанию всё выключено, включается в
`board.blackpill_p3steel.h`:

```
#define DISPLAY_TYPE_SSD1306      // или DISPLAY_TYPE_HD44780
#define DISPLAY_MENU              // меню; без него только экран состояния
#define BUTTON_UP_BIT            0
#define BUTTON_DOWN_BIT          1
#define BUTTON_OK_BIT            2
#define BUTTON_BACK_BIT          3   // необязательна
```

**Дисплеи** (один из двух):

| | `DISPLAY_TYPE_SSD1306` | `DISPLAY_TYPE_HD44780` |
|---|---|---|
| Что | OLED 0,96" 128×64; 0,91" 128×32 — `DISPLAY_HEIGHT 32`; 1,3" на SH1106 — `DISPLAY_SH1106` | ЖК 20×4 с платой PCF8574 («LCD2004 I2C»); 16×2, 20×2, 16×4 — `DISPLAY_COLS`, `DISPLAY_LINES` |
| Текст | 21×8 (21×4) символов 6×8 точек | 20×4 символа |
| Адрес I2C | 0x3C (0x3D) | 0x27 (PCF8574T), 0x3F (PCF8574AT) |
| Питание | 3,3 В | 5 В |

Адрес меняется через `DISPLAY_I2C_ADDRESS` (7 бит), перевёрнутый OLED —
`DISPLAY_ROTATE_180`. Подключение: VCC, GND, SDA → PB7, SCL → PB6.
Плата ЖК подтягивает SDA/SCL к 5 В — PB6/PB7 это допускают (выводы FT).

**Кнопки** — на расширителе PCF8574 (тот же, что включает вентиляторы,
адрес 0x20), каждая между выводом и GND, подтяжка встроена в PCF8574:

| Вывод | Назначение |
|-------|------------|
| P0 | вверх |
| P1 | вниз |
| P2 | OK |
| P3 | назад (необязательна: в каждом меню есть пункт «Back») |
| P4, P5 | свободны |
| P6, P7 | вентиляторы хотэнда и контроллера |

Расширитель читается каждые 10 мс (чтение одного байта по I2C),
нажатие засчитывается после двух одинаковых чтений (антидребезг).
Вверх/вниз при удержании повторяются: через 0,4 с — каждые 100 мс, через
2 с — каждые 50 мс с шагом ×10.

**Экран состояния** (есть и без меню): температуры (текущая/заданная),
обдув и скорость (`M220`), координаты, печать с SD (процент и время),
последняя строка — сообщение `M117` или состояние: Ready, Heating...,
имя печатаемого файла, «Power loss: resume?», «Filament change».
Раскладка зависит от размера: 8, 4 или 2 строки.

**Меню.** OK на экране состояния открывает меню:

- **Main**: Status; Resume print / Discard print — после пропадания
  питания; Continue — во время смены филамента (`M600`); во время
  печати — Pause print / Resume print, Stop print, Tune; иначе — Print
  from SD, Motion; Temperature; Settings (не во время печати).
- **Print from SD**: файлы G-кода (расширение на G: `.GCO`, `.G`) и
  подкаталоги, Refresh, Mount card (если карта не смонтирована). Выбор
  файла → подтверждение → печать (`M23` + `M24`), меню закрывается.
  Без SD-карты — файлы в SPI flash.
- **Tune**: скорость % (`M220`), поток % (`M221`), хотэнд, стол, обдув,
  babystep Z (каждый шаг сразу, `M290`), смена филамента (`M600`).
- **Temperature**: хотэнд, стол, обдув, преднагрев PLA и PETG
  (`PREHEAT_PLA_HOTEND`, `PREHEAT_PLA_BED` и т. д., по умолчанию 200/60 и
  240/80), охлаждение.
- **Motion**: Home all (`G28`), Auto level (`G28` + `G29`, с
  `BED_LEVELING`), Align Z (`G34`), Move X/Y/Z (только по осям, где
  был хоуминг), Steppers off (`M84`).
- **Settings**: шаги/мм XYZE (`M92`), максимальные скорости (`M203`),
  ускорения печати, перемещения и ретракта (`M204`), максимальные
  ускорения (`M201`), рывок (`M205`), K linear advance (`M900`), смещение
  зонда Z (`M851`), длина и скорость ретракта (`M207`); Store settings
  (`M500`, в SPI flash), Load settings (`M501`), Defaults (`M502`, с
  подтверждением).
- **Stop print** (с подтверждением): чтение файла прекращается, очередь
  движений сбрасывается (как `M410`), нагреватели и обдув выключаются,
  Z поднимается на 10 мм, запись восстановления после пропадания питания
  стирается.

Значение правится на отдельном экране: вверх/вниз, OK — установить,
назад — отмена. Через 60 с без нажатий (`MENU_TIMEOUT`) меню закрывается.

**Как устроено.** Меню работает каждые 10 мс из `clock_poll()`, то есть
и во время долгих команд (хоуминг, нагрев). Само оно ничего не
выполняет: складывает строки G-кода в очередь, а основной цикл выполняет
их между командами (раньше команд хоста и строк файла) — как команды
хоста, только без `ok`. Поэтому значения из меню проходят те же проверки,
что `M104` или `M92` от хоста, а Store settings — это `M500`. Во время
печати команда из меню ждёт свободного места в очереди движений, как и
команды хоста.

Экран — текстовый буфер в ОЗУ. На дисплей уходят только изменившиеся
символы, понемногу из `clock_poll()`, без ожидания, поэтому нет ни
мерцания, ни пауз в работе. Для OLED используется моноширинный шрифт 5×7
(ячейка 6×8), поэтому текст лежит сеткой, как на ЖК.

Шина I2C общая: дисплей, чтение кнопок и выходы вентиляторов идут через
одну очередь передач, у каждой свой адрес. Драйвер I2C теперь умеет и
чтение одного байта (для кнопок).

**Отключение:** без `DISPLAY_TYPE_*` дисплея нет, без `DISPLAY_MENU`
дисплей показывает только состояние, без `BUTTON_*_BIT` кнопки не
опрашиваются.

## Таймер и статистика печати (`M31`, `M75`–`M78`), `M997`

| Команда | Действие |
|---------|----------|
| `M75` | Запустить таймер (после `M76` — продолжить). Также запускают `M109`/`M190` с целью и `M24`. |
| `M76` | Пауза таймера (также `M25`). |
| `M77` | Остановить: печать засчитывается как законченная. Также останавливают конец файла SD/SPI flash и `M104 S0` / `M109 S0` — когда движения доедут. |
| `M31` | Время текущей или последней печати: `echo:Print time: 1h 2m 3s`. |
| `M78` | Статистика: `echo:Stats: Prints: 5, Finished: 4, Failed: 1`, общее и самое долгое время, израсходованный филамент (движения E вперёд при идущем таймере). `M78 S78` — сброс. |
| `M997` | Перезагрузка в системный загрузчик STM32 (USB DFU), как с нажатой BOOT0: прошивка через `dfu-util -a 0 -s 0x08000000:leave -D teacup.bin` или STM32CubeProgrammer. |

«Failed» — печати, которые начались и не закончились (пропало питание,
аварийная остановка). Статистика хранится автоматически (не по `M500`)
отдельной записью в секторе настроек: при начале и конце печати, когда
очередь движений пуста. При стирании полного сектора последняя запись
другого вида (настройки или статистика) переписывается обратно.

**M997.** Независимый сторожевой таймер нельзя остановить, а загрузчик
его не сбрасывает. Поэтому `M997` пишет метку в резервный регистр RTC
(BKP0R) и перезагружает МК; при старте, до настройки тактирования и
сторожевого таймера, прошивка видит метку, стирает её и переходит в
загрузчик (системная память по адресу 0, VTOR, стек и вектор сброса
загрузчика). Нагреватели перед этим выключаются.

## PrusaSlicer и Pronterface

### PrusaSlicer

- **G-code flavor:** Marlin 2.
- **Arc fitting:** можно включать, `G2`/`G3` поддерживаются (см. «Дуги
  G2/G3»). Файл получается меньше, а поток команд по USB/UART реже
  упирается в скорость связи.
- **Machine limits.** Если выбрано «Emit to G-code», команды
  `M201`/`M203`/`M204`/`M205` из файла перезапишут настройки принтера, как
  в Marlin. Поэтому задайте в слайсере реальные значения (для P3 Steel,
  например, `M203 Z4`) или выберите «Use for time estimate only».

Что прошивка делает со строками, которые генерирует PrusaSlicer:

- **Команды Prusa принимаются без вреда.** `M862.x`, `G80` (и `M900` в
  сборках без `LINEAR_ADVANCE`) получают ответ `echo:Unknown command` и
  `ok`. В сборке P3 Steel `M900 K` задаёт linear advance. Текст в кавычках
  (`M862.3 P "MK3S"`) не разбирается как G-код.
- **`G28 W`** — хоуминг всех осей (параметр `W` игнорируется).
- **`G4 S<сек>`** и **`M73 P/R`** поддерживаются; `M73 Q/S` принимаются
  молча.
- **Параметры осей в M-командах не меняют цель движения.** Например, после
  `M84 X Y E` следующий `G1 Z…` не уедет по X в ноль.
- **Пока выполняются `M109`/`M190`/`M116`,** раз в секунду выводится строка
  `T:…/… B:…/…`, как в Marlin, — графики температуры в хосте не замирают.

### Pronterface

- **Подключение:** кабель USB к разъёму Black Pill, порт COMx / ttyACM0,
  скорость любая. Дополнительно можно подключиться через USB-UART
  адаптер на PA2/PA3 (115200 бод), например вторым терминалом.
- **Кнопка Reset** не работает: сброс по DTR не поддерживается. После
  `M999` плата перечисляется заново, нажмите «Connect».
- **Протокол:** номера строк, контрольные суммы, `M110 N-1`, пересылка
  (`Resend`) и ответ `ok T:…` работают так, как ожидает printcore — модуль
  связи Pronterface.
- **Окно SD** получает маркеры `Begin file list` / `End file list`.

## Оптимизации шагового прерывания

- **Конец STEP-импульса по второму каналу таймера.** Шаговое прерывание
  больше не ждёт `MIN_STEP_PULSE_US` в цикле. Второй канал сравнения TIM5
  (CC2) через это время вызывает прерывание, которое опускает все STEP-пины.
  Исключение — `ACCELERATION_TEMPORAL`: там по-прежнему короткое ожидание.
- **Одна запись в BSRR на порт.** Шаги всех осей собираются и выводятся
  одной записью в регистр BSRR на каждый используемый порт. Маски
  вычисляются при компиляции. Z и Z2 на одном порту шагают строго
  одновременно.
- **Ленивое сохранение FPU-регистров** включено явно. Прерывания, которые
  не используют FPU, не тратят время на сохранение его регистров.
- **Критические секции через BASEPRI.** Секции основного цикла, общие с
  UART, I2C и SysTick (`ATOMIC_START_NOSTEP()`), шаговое прерывание не
  блокируют. Секции, общие с шаговым прерыванием, по-прежнему запрещают
  все прерывания.
- **Концевики по прерываниям EXTI.** Фронт на пине концевика сразу
  запускает проверку (через PendSV), без ожидания `ENDSTOP_STEPS` опросов.
  - Опрос раз в 2 мс остаётся: он ловит концевик, который уже нажат в
    момент начала движения.
  - `NO_ENDSTOP_INTERRUPTS` отключает прерывания и оставляет только опрос.
  - Если два концевика на одной линии EXTI (например, PA12 и PB12),
    второй только опрашивается.

**`M9001` — статистика шагового прерывания** (`M9001 R` — сброс):
длительность в тактах (min/avg/max), максимальная задержка входа в
прерывание, доля CPU, число шагов, запланированных с опозданием.
Используйте её для замеров на реальной плате: Renode не моделирует такты
точно (задержки Flash, кэш ART).

**Мультишаг (`MULTISTEPPING`, по умолчанию выключен).** Как в Marlin:
если интервал между шагами меньше `MULTISTEP_MIN_CYCLES` тактов (по
умолчанию 840 — 100 кГц при 84 МГц), прерывание делает 2 шага и приходит
вдвое реже, при ещё меньшем интервале — 4, до `MULTISTEP_MAX` (8). Между
шагами одного прерывания выдерживаются длительность импульса и пауза
(`STEP_PULSE_CYCLES` каждая), для таймерных импульсов тоже.

Когда это выгодно. Каждый дополнительный шаг в прерывании стоит
2 × `STEP_PULSE_CYCLES` ожидания (DRV8825: 2 мкс + 2 мкс ≈ 370 тактов), а
само прерывание в Renode — около 100–200 тактов. Поэтому мультишаг
снижает нагрузку, только если прерывание на плате дольше ожидания, и
нужен как защита на очень высоких частотах шагов. На P3 Steel частоты до
41,8 кГц (ретракт E 25 мм/с × 1672 шага/мм), Z 32 кГц, X/Y 24 кГц:
интервал 2000 тактов и больше, при пороге 840 мультишаг не включается.
Если `M9001` на плате покажет среднюю длительность прерывания больше
~400 тактов или долю CPU больше 30 %, включите `#define MULTISTEPPING` и
поднимите `MULTISTEP_MIN_CYCLES` (например, 3000 — мультишаг от 28 кГц).

## UART через DMA

`hal/uart.c` содержит две реализации с одинаковым интерфейсом. По
умолчанию используется DMA (`SERIAL_DMA`), `NO_SERIAL_DMA` возвращает
вариант на прерываниях.

**Приём.** DMA складывает каждый символ в кольцевой буфер на 256 байт,
прерываний на каждый символ нет. Прерывания бывают только два:

- когда линия замолкает (флаг IDLE, через время одного символа после
  последнего);
- когда DMA доходит до конца буфера и начинает сначала — на случай, если
  хост шлёт без пауз.

В обоих новые символы передаются emergency-парсеру (`M112`, `M108`,
`M410`) и проверяется заполнение буфера для XON/XOFF.

**Передача.** Кольцевой буфер на 256 байт уходит блоками через DMA:
одно прерывание на блок, а не на каждый символ. XON/XOFF отправляется
сразу, минуя буфер.

**Когда прерывания запрещены** (остановка после ошибки, `printer_kill()`),
приём продолжает работать через DMA-буфер, а окончание передачи
проверяется опросом флага. `M999` и сообщения об ошибке работают как
обычно.

**Каналы DMA** выбираются по `SERIAL_UART` и не пересекаются с каналом
АЦП (DMA2 stream 0):

| UART | Приём | Передача |
|------|-------|----------|
| USART1 | DMA2 stream 2, канал 4 | DMA2 stream 7, канал 4 |
| USART2 | DMA1 stream 5, канал 4 | DMA1 stream 6, канал 4 |
| USART6 | DMA2 stream 1, канал 5 | DMA2 stream 6, канал 5 |

UART — один из портов хоста; раздачу вывода по портам делает
`hal/serial.c`, сам драйвер UART находится в `hal/uart.c` (см. «Порты: USB
CDC и UART»).

## SPI flash на плате Black Pill (`SPI_FLASH`)

На нижней стороне плат WeAct Black Pill есть площадка U3 под микросхему
SPI flash (SOIC-8). Она подключена к SPI1:

| Сигнал | Пин |
|--------|-----|
| CS | PA4 |
| CLK | PA5 |
| DO (MISO) | PA6 |
| DI (MOSI) | PA7 |

Поддерживаются W25Q16…W25Q128 и совместимые (стандартные команды,
3-байтовые адреса, до 16 МБ). Микросхема определяется по JEDEC ID при
старте, например `echo:SPI flash: manufacturer 0xEF type 0x40, 8192 kB`.
Без микросхемы прошивка работает как раньше: настройки хранятся во
внутренней Flash, файлов нет.

Опция включается в файле платы. В `board.blackpill_p3steel.h` она уже
включена, а термисторы для этого перенесены на PA1 и PB1. Шина SPI1
(PA5–PA7) общая с SD-картой, если та подключена.

### Настройки (`SPI_FLASH_SETTINGS`, включено вместе с `SPI_FLASH`)

`M500` пишет настройки в первый сектор микросхемы (4 КБ) в том же
формате, что и во внутреннюю Flash. Преимущества:

- стирание не останавливает CPU;
- `M500` не ждёт окончания движений и работает во время печати;
- внутренняя Flash не изнашивается.

`NO_SPI_FLASH_SETTINGS` оставляет настройки во внутренней Flash.

### Файлы G-кода (`SPI_FLASH_FILES`)

Включено по умолчанию, если SD-карта не настроена. Микросхема работает
вместо SD-карты, команды те же:

| Команда | Действие |
|---------|----------|
| `M28 ИМЯ.GCO` … `M29` | Загрузить файл (в Pronterface — «Upload to SD»). Строки между командами записываются в файл, а не выполняются. |
| `M20` | Список файлов. |
| `M23 ИМЯ` | Выбрать файл. |
| `M24` / `M25` | Начать / приостановить печать. |
| `M26 S<байт>` | Перейти к позиции в файле. |
| `M27` | Статус печати. |
| `M30 ИМЯ` | Удалить файл. |
| `M9002` | Удалить все файлы. |

Имена — до 12 символов (формат 8.3).

**Устройство хранения.** Каталог — сектор по адресу 0x1000 (128 записей),
данные файлов — с адреса 0x2000, каждый файл начинается с границы
сектора. Сектор стирается в момент, когда запись в него начинается.

**Ограничение: уплотнения нет.** Новые файлы пишутся за последним.
Когда место закончилось, а файлов не осталось (все удалены через `M30`),
каталог стирается и запись начинается сначала. `M9002` делает это сразу.
Если место закончилось, а файлы ещё есть, удалите их все, чтобы
освободить место.

### SD-карта на шине SPI flash (`SD_CARD_SELECT_PIN`)

SD-карту можно подключить в режиме SPI к той же шине SPI1, что и SPI
flash (и MAX31865, если он есть). Включается в `board.blackpill_p3steel.h`:

```
#define SD_CARD_SELECT_PIN       PC_14
```

**Подключение:**

| SD-карта (модуль) | Black Pill |
|-------------------|------------|
| VCC | 3,3 В |
| GND | GND |
| SCK (CLK) | PA5 |
| MISO (DO) | PA6 |
| MOSI (DI, CMD) | PA7 |
| CS | PC14 (кварц 32,768 кГц на PC14/PC15 снять) |

Карта работает от 3,3 В, как и STM32, поэтому преобразователь уровней не
нужен. Подойдёт модуль без преобразователя или такой, у которого
выходной буфер MISO выключается сигналом CS. **Дешёвые модули с
микросхемой 74LVC125** (на 5 В, с регулятором) часто держат MISO
включённым всегда. Одна такая карта работает, но SPI flash и MAX31865 на
той же шине перестают отвечать: flash при старте «не найдена», датчик
выдаёт ошибки. Проверка: при CS карты = 1 (карта не выбрана) линия MISO
должна «отпускаться» — подтяжка к 3,3 В на PA6 её поднимает.

**Что делает прошивка:**

- Карта монтируется при старте (`echo:SD card ok` или
  `echo:SD init fail`), `M21` — после смены карты, `M22` — извлечь.
  Детектора карты нет: PC15 занят Z2 или MAX31865.
- `M20`, `M23`, `M24`, `M25`, `M26`, `M27` работают с картой; файлы в
  SPI flash (`SPI_FLASH_FILES`) при этом выключены, загрузки `M28` нет
  (Petit FatFs только читает). SPI flash по-прежнему хранит настройки
  (`M500`) и записи восстановления после пропадания питания: `M1000`
  продолжает печать с карты.
- Файловые системы FAT16 и FAT32: обычная карта SDHC (до 32 ГБ, с
  завода в FAT32); SDXC (от 64 ГБ, с завода exFAT) — только после
  форматирования в FAT32. Карты SDv1, SDv2 и MMC. Разделы — таблица
  MBR или «суперфлоппи». Имена в формате 8.3, длинные имена видны как
  короткие (`LONGFI~1.GCO`). Подкаталоги на два уровня.
- Сообщения как у Marlin, их ждут OctoPrint и Pronterface: `M20` — `Begin
  file list`, `ИМЯ.GCO размер`, `ПАПКА/ИМЯ.GCO размер`, `End file list`
  (скрытые и системные файлы не показываются); `M23` — `File opened: ИМЯ
  Size: N` и `File selected` или `open failed, File: ИМЯ.`.

**Общая шина.** Все устройства работают в режиме SPI 0 (MAX31865 — в
режиме 1, он переключает режим сам); скорость каждое выставляет перед
обменом: карта — 400 кГц при инициализации и ~10 МГц при чтении, flash —
~10 МГц, MAX31865 — 400 кГц. Все CS поднимаются в `spi_init()` до первого
обмена. Во время обмена с одним устройством к другим не обращаются:

- команды из файла на карте выполняются, когда карта уже отпущена.
  Раньше команда выполнялась прямо из чтения сектора, при выбранной карте:
  `M500` (запись flash), ожидание температуры или `G4` (опрос MAX31865),
  запись восстановления попали бы на шину одновременно с картой;
- flash отпускает CS на время ожидания стирания и записи.

**Исправлено в чтении файла** (`pf_parse_line()`):

- чтение останавливается на конце файла, а не его последнего сектора. В
  остатке сектора лежат старые данные (например, удалённого файла), они
  попадали в парсер как G-код;
- последняя строка без перевода строки выполняется;
- пустые строки пропускаются, CR LF (файлы из Windows) — одна строка;
- ожидание готовности карты при инициализации (до 1 с) сбрасывает
  watchdog (340–940 мс): медленная карта перезагружала принтер на `M21`.

### Восстановление после пропадания питания (`POWER_LOSS_RECOVERY`, `M413`, `M1000`)

Имеет смысл только при печати с SD-карты или из файлов в SPI flash: при
печати с компьютера файл у хоста. Записи хранятся в последних 8 КБ SPI
flash (область файлов на столько меньше); без микросхемы функция
выключена.

**Что записывается.** При каждой смене слоя (Z изменился, не чаще раза
в 2 с; учитывается и `G92 Z0` после хоуминга) и не реже чем раз в `PLR_INTERVAL` секунд (30): имя файла, начало
строки файла, из которой получено **выполняемое сейчас** движение, X Y Z
E и F перед этой строкой, температуры, вентилятор, режим E, `M220`/`M221`.
Очередь движений (64) читает файл далеко вперёд, поэтому конец очереди —
не то место, где принтер сейчас: каждое движение несёт с собой свою
строку файла. При возобновлении печать идёт заново с этой строки:
ничего не пропадает, а напечатанное после записи (не больше одного слоя
или `PLR_INTERVAL` секунд) печатается повторно.

Записи по 128 байт с номером и CRC пишутся друг за другом в два сектора
по кругу; сектор стирается при входе в него, новейшая запись всегда в
другом секторе. Стирание (около 50 мс) при печати из SPI flash только
приостанавливает чтение файла, очередь движений это покрывает.

**После включения** прошивка сообщает:

```
echo:Power loss recovery: PRINT.GCO at byte 12345, Z1.200. M1000 resumes, M1000 C discards
```

`M1000`:

1. нагревает стол, затем хотэнд (с ожиданием);
2. принимает Z как был (винты держат его без питания), поднимает на
   `PLR_Z_RAISE` (2 мм), хоумит X и Y;
3. выдавливает `PLR_PURGE_LENGTH` (3 мм), возвращается к X/Y, опускается;
4. восстанавливает F, режим E, `M220`/`M221`, вентилятор и продолжает
   файл.

`M1000 C` удаляет запись, `M413 S0`/`S1` выключает/включает запись
(`M500` сохраняет), `M413` выводит состояние. Законченная печать и выбор
нового файла (`M23`) запись удаляют.

## STEP-импульсы таймерами (`STEP_TIMER_PULSES`)

Опция включена в конфигурации P3 Steel, в остальных выключена.
Реализация — в `hal/step_timers.c`.

**Как работает.** Если STEP-пин оси — выход канала таймера, этот таймер
работает в режиме одного импульса (One-Pulse Mode, PWM mode 2, CCR = 1,
ARR = длительность импульса). Шаговое прерывание делает для оси одну
запись `CR1 = OPM | CEN`, импульс нужной длительности формирует
аппаратура. Прерывание конца импульса нужно только для осей на GPIO.

**Когда ось остаётся на обычных GPIO-импульсах.** Решение принимается
при старте для каждой группы осей отдельно (X, Y, Z вместе с Z2, E):

- у пина нет канала таймера;
- таймер — TIM5 (он задаёт время шагов);
- таймер занят нагревателем для ШИМ;
- таймер уже взят другой группой осей;
- Z и Z2 на разных таймерах.

При старте выводится итог распределения, например
`echo:Step pulses: X TIM1 Y TIM2 Z gpio E TIM3`.

Для P3 Steel опция включена, выводится `X TIM1 Y TIM2 Z gpio E TIM3`
(см. «Распиновка P3 Steel»). Прерывание конца импульса остаётся только
для шагов Z.

С `ACCELERATION_TEMPORAL` опция не работает (выдаётся `#warning`).

## Планировщик на FPU (float)

Весь планировщик считает в float на FPU Cortex-M4F, без целочисленных
обходов времён AVR:

- **Длина движения** — точный `sqrtf(dx² + dy² + dz²)` (`distance_3d_f()`
  в `motion/dda_maths.c`, VSQRT около 14 тактов). Старые приближения
  `approx_distance()` / `approx_distance_3()` ошибались на −3…+4 % в XY, а
  3D-вариант из-за ошибки в сортировке осей давал движение X100 + Z0,5 на
  17 % короче.
- **Скорость на каждом шаге** считается прямо в шаговом прерывании:
  интервал c = c0 / (2·√n), n — позиция на рампе (минимум из разгона от
  скорости входа и торможения до скорости выхода), не меньше крейсерского
  `c_min`. Раньше скорость пересчитывалась раз в 2 мс в `dda_clock()` и
  держалась ступенькой до следующего пересчёта; теперь разгон плавный с
  точностью до шага. `dda_clock()` остался для концевиков, опережения
  linear advance и мощности лазера `M4`.
- **Время и скорость движения** (`move_duration`, `c_min`, пределы осей по
  `M203`, ускорение вдоль пути, стыковка `dda_find_crossing_speed()`) — в
  float. Ушли ограничения от переполнений: `F` больше не обрезается до
  65535 мм/мин, пропали ветвления по `msbloc()`, `MAX_DELTA_UM` теперь
  только длина поиска при хоуминге.
- **мкм ↔ шаги** без деления: для каждой оси при `M92` один раз считается
  k = ⌊mult·2³²/div⌋, дальше `mul_div_k()` — четыре UMULL и одна поправка
  остатка. Результат и округление точно как у прежней `muldiv()` (она
  осталась для редких мест, например датчика филамента: UMULL + UDIV).
  Побитовый `muldivQR()` (до 32 итераций на вызов, несколько вызовов на
  движение), `int_sqrt()`, `int_inv_sqrt()`, `int_f_sqrt()` и `msbloc()`
  удалены.

Короткие отрезки кривых ставятся в очередь быстрее: `dda_create()` на
отрезке 0,35 мм теперь обходится без целочисленных делений 64/32.

## Lookahead по всей очереди

Раньше lookahead стыковал только два соседних движения, и каждое новое
движение должно было успевать остановиться в собственных пределах. Это
давало потолок скорости v = √(2·a·L) независимо от `F`: на отрезках 0,35 мм
при 1000 мм/с² около 26 мм/с, на отрезках дуг 0,63 мм около 35 мм/с. На
закруглённых периметрах скорость «пилила» при почти постоянном давлении в
сопле, отсюда наплывы и «прыщи».

Теперь после каждого нового движения `dda_plan()`
(`motion/dda_lookahead.c`) пересчитывает скорости всей очереди:

1. От нового движения назад до самого старого движения, скорость входа
   которого ещё может измениться.
2. Обратный проход: каждое движение должно успеть затормозить до скорости
   входа следующего, новое движение — до нуля.
3. Прямой проход: каждое движение должно успеть разогнаться до скорости
   выхода. Результат записывается по одному стыку.

Ограничение на стыке прежнее: `dda_find_crossing_speed()` по рывкам
`M205`, не выше `F` обоих движений. Скорости считаются вдоль пути в
квадрате, (мм/мин)², на FPU. У каждого движения своё ускорение вдоль пути
(`M204 P`/`R`/`T` и `M201`, см. «Настройки во время работы»).

**Согласованность с шаговым прерыванием.** Профиль скорости в
`dda_step()` (на каждом шаге) — минимум из разгона от скорости входа (`start_steps`),
торможения до скорости выхода (`end_steps`) и крейсерской скорости
(`c_min`). Точки перехода `rampup_steps`/`rampdown_steps` для этого не
нужны, поэтому скорость на стыке меняется записью двух чисел: `end_steps`
одного движения и `start_steps` следующего. Они пишутся вместе при
запрещённых прерываниях и только если первое движение ещё не началось.
Если движение успело начаться, его стыки больше не меняются, а
планирование начинается заново с уже записанными стыками.

**Скорость расчёта.** Скорость входа, которая уже не может вырасти
(достигла предела стыка или получена полным разгоном от такой же), помечается
(`plan_fixed`), и следующие проходы на ней останавливаются. Обычно
пересчитываются только последние движения, которые входят в участок
торможения в конце очереди.

**Глубина очереди.** Чтобы ехать со скоростью v, в очереди должно быть
v² / (2·a) пути для остановки. У P3 Steel `MOVEBUFFER_SIZE` поднят с 16 до
64: 64 отрезка по 0,35 мм — это 22 мм, хватает на 200 мм/с при
1000 мм/с². Одно движение занимает 120 байт ОЗУ, 64 движения — 7,7 КБ;
всего `.bss` сборки P3 Steel 17,6 КБ из 64 КБ у STM32F401CC.

**Ограничения.**

- Первое движение после пустой очереди стартует сразу и заканчивается
  остановкой (как и раньше): пока оно едет, следующие к нему не
  пристыковать.
- Движения с проверкой концевиков (хоуминг, зонд) теперь явно ни с чем не
  стыкуются: их торможение после срабатывания рассчитано на остановку.
- При разных шагах на мм по X и Y (`M92`) стыковки нет, как и раньше.

**Точный квадратный корень в разгоне.** Интервал шага на позиции n разгона
считается как c0 / (2·√n). Раньше √n округлялся до целого
(`int_f_sqrt()`). Это незаметно, пока движение разгоняется с нуля. Но с
полным lookahead движения идут у вершины разгона, где n — всего несколько
сотен (у P3 Steel около 400 на 100 мм/с по диагонали). Одна единица √n там
— скачок скорости на 5 %, и на отрезках около 45° скорость проседала до
94 %. Теперь `dda_c_for_n()` берёт √n на FPU без округления, прямо в
шаговом прерывании на каждом шаге.

## Linear advance (`LINEAR_ADVANCE`, `M900 K`)

Давление в сопле отстаёт от экструдера. При разгоне выходит меньше
пластика, чем нужно, при торможении — больше: раздутые углы, наплыв на
шве. Linear advance ведёт экструдер впереди номинальной позиции на

```
опережение = K × скорость подачи филамента     (K в секундах, как в Marlin)
```

Поэтому при разгоне экструдер подаёт лишний пластик, а при торможении
забирает его обратно, в том числе шагами назад. Для директа K обычно
0,02–0,1, для боудена 0,2–1. В сборке P3 Steel опция включена, K по
умолчанию 0 (`LINEAR_ADVANCE_K`), значение задаётся `M900 K0.05` и
сохраняется `M500`.

**Почему нужен отдельный генератор шагов E.** В движении E — одна из осей
Брезенхема: она шагает вместе с «быстрой» осью, не больше одного шага за
прерывание и только в направлении движения. Шагов опережения на малой
скорости больше, чем шагов быстрой оси, и при торможении они идут против
движения. Поэтому со сборкой `LINEAR_ADVANCE` (`motion/linear_advance.c`):

- `dda_step()` только считает шаги E Брезенхема (номинальная позиция);
- `dda_clock()` раз в 2 мс считает опережение из текущей скорости
  (K × шаги E в секунду) и передаёт генератору. Изменение растягивается
  равномерно на следующие 2 мс, без пачек шагов;
- генератор E ведёт мотор к «номинал + опережение» по одному шагу, не
  чаще, чем раз в три длительности импульса, и сам переключает DIR (с
  выдержкой 2 мкс перед шагом). Он работает в том же шаговом прерывании
  (канал сравнения 4 таймера TIM5, сразу после шага Брезенхема), поэтому
  с основными шагами не конкурирует.

**Какие движения получают опережение** (как в Marlin): печатающие — X
или Y вместе с E вперёд, если филамента не больше 3 мм на мм пути.
Ретракты, подачи, холостые перемещения опережения не получают. Ускорение
печатающих движений ограничивается так, чтобы добавка скорости E при
разгоне (K × ускорение × E на мм пути) не превышала рывок E (`M205 E`).
При малом K это ограничение не срабатывает.

`M400` и хоуминг ждут, пока экструдер заберёт опережение после последнего
движения. `M410` и аварийный останов оставляют экструдер где он есть.

## Input shaping и S-кривая (`INPUT_SHAPING`, `M593`)

Рама и особенно тяжёлый стол i3 по Y звенят после каждого резкого
изменения ускорения: на стенках за углами видна «рябь». Input shaping
подавляет звон на резонансной частоте оси. Движение раскладывается на две
(ZV) или три (MZV) задержанные копии меньшего размера так, чтобы
возбуждённые ими колебания гасили друг друга:

```
x_формир(t) = Σ A[k] · x(t − T[k])
ZV:  A = 1, K;               T = 0, td/2
MZV: A = a, (√2−1)K, aK²;    T = 0, 0,375·td, 0,75·td     (a = 1 − 1/√2)
td = 1 / (f·√(1 − ζ²)), K = exp(−ζπ/√(1 − ζ²)) (для MZV с множителем 0,75)
```

Формулы как в Klipper, веса нормированы к сумме 1. ZV даёт наименьшую
задержку (td/2), MZV (0,75·td) меньше чувствителен к ошибке в частоте.

**S-кривая** — сглаживание X/Y скользящим средним за время `S`.
Постоянное ускорение превращается в ускорение, которое нарастает и спадает
за `S` (ограниченный рывок). Сглаживание работает во времени, поэтому
действует и через стыки коротких отрезков. Классическая S-кривая по
отдельным движениям (как в Marlin) на коротких отрезках, наоборот,
обнуляла бы ускорение на каждом стыке.

**Как это сделано.** Как и linear advance, всё работает на уровне шагов,
и позиция остаётся точной:

- `dda_step()` не шагает X и Y, а записывает каждый шаг Брезенхема
  (время по таймеру и направление) в историю (`INPUT_SHAPING_BUFFER`
  шагов на ось);
- для каждой копии k два указателя идут по истории: шаг входит в окно
  копии в момент t + T[k] и выходит из него через S. Вышедшие шаги
  считаются целиком, шаги внутри окна — долей времени, проведённого в
  окне;
- генератор (`motion/input_shaping.c`) ведёт мотор к округлённой
  формированной позиции по одному шагу, не чаще раза в три длительности
  импульса, и сам переключает DIR. Следующий запуск он планирует на
  ближайшее событие копии или на момент, когда сглаженная позиция уйдёт на
  полшага. Генератор работает в том же шаговом прерывании, что и E
  linear advance: оба сидят на канале 4 таймера TIM5 и через общий
  диспетчер (`hal/timer.c`) говорят, когда им нужно проснуться.

Каждый номинальный шаг выдаётся ровно один раз, поэтому `M114` и конечные
позиции не меняются. Движения с проверкой концевиков (хоуминг, зонд) идут
без формирования: задержанная ось остановилась бы дальше, чем увидел
концевик. E и Z не формируются, как и в Klipper: экструзия опережает XY на
среднюю задержку (у ZV 40 Гц это 6 мс). `M400` и хоуминг ждут, пока X/Y
отработают задержанные шаги. `M410` даёт им доработать, чтобы позиция
осталась верной.

**Настройка.** В сборке P3 Steel опция включена, но частоты по умолчанию
0 (выключено), S = 0.

1. Напечатайте башню для звона (ringing tower): стенки со скоростью v,
   высоким ускорением, без S-кривой.
2. Измерьте расстояние d между соседними волнами за углом. Частота
   f = v / d, отдельно для X и для Y (стол — Y).
3. Задайте частоты, например `M593 Y F32 T1` и `M593 X F48 T1`,
   демпфирование по умолчанию `D0.1`, проверьте и сохраните `M500`.
4. S-кривая: `M593 S5`…`S10` для ещё более мягкого разгона.

Формирование и S-кривая немного скругляют углы: за время задержки или
окна ось ещё догоняет, у острого угла на скорости v отклонение порядка
v·T/8. При разумных частотах (от 25 Гц) и S до 10 мс это сотые доли
миллиметра.

**Память и нагрузка.** История — 4 байта на шаг: у P3 Steel 2048 шагов
на ось, 16 КБ на X и Y, всего `.bss` 35 КБ из 64 КБ STM32F401CC. Этого
хватает на (наибольшая задержка + S) × максимальная частота шагов: MZV 25 Гц
с S = 10 мс — 40 мс, это 960 шагов на 150 мм/с. Если история всё же
заполнится, шаг выдаётся без формирования (позиция остаётся верной), а
`M593` сообщает `history overflows`. Генератор тратит несколько сотен
тактов на шаг X/Y (FPU, одинарная точность).

**Шаговый таймер.** Задержанные шаги хранят время по счётчику TIM5,
поэтому счётчик больше не обнуляется при старте из пустой очереди:
`timer_reset()` только отсчитывает следующий шаг от текущего момента.
Шаг, время которого уже прошло, запускается программно (флаг и
отложенное прерывание), а не записью в `EGR`. На STM32 `EGR` сработал бы,
но модель таймера в Renode при любой записи в `EGR` обнуляет счётчик. Раз
в 2 мс SysTick проверяет, не пропущено ли сравнение (просрочено больше
чем на 1 мс, а флага нет), и запускает такой шаг сам. На STM32 так не
бывает, а модель Renode при крупном кванте времени изредка пропускает
сравнение, выставленное впритык к счётчику.

## Перекос XY (`SKEW_CORRECTION`, `M852`)

Если рама не идеально прямоугольная, ось Y стоит к X не под 90°, и
квадрат печатается ромбом. Коррекция как `SKEW_CORRECTION` в Marlin:

```
мотор X = X − Y · k        k = tg(угла перекоса)
```

Это одно умножение при переводе позиции в шаги (`dda_kinematics.c`, для
декартовой кинематики и CoreXY) и обратное — в `M114`. Координаты G-кода,
программные границы, сетка стола не меняются.

**Как измерить.** Напечатайте квадрат (например 100 × 100 мм, тонкий,
в один-два слоя) и измерьте диагонали: AC — от переднего левого угла к
заднему правому, BD — от переднего правого к заднему левому. Тогда

```
k = (AC² − BD²) / (AC² + BD²)
```

Пример: AC = 141,70 мм, BD = 141,14 мм → k = 0,00396. Задайте
`M852 I0.00396`, напечатайте квадрат ещё раз (диагонали должны сойтись),
сохраните `M500`. `S` — то же, что `I`. Допустимо −0,1…0,1; `M852 I0` —
выключено. Смена `k` не двигает головку: текущая позиция остаётся с теми
же координатами. По умолчанию `XY_SKEW_FACTOR` = 0.

**Перекос XZ и YZ** (`M852 J K`, как в Marlin): вертикальные стойки
наклонены вперёд/назад или вбок, и высокие детали «заваливаются».

```
мотор Y = Y − Z · K
мотор X = X − мотор Y · I − Z · J
```

Как измерить: напечатайте высокий тонкий куб или стойку, измерьте смещение
верха относительно низа по X (d_x) и по Y (d_y) на высоте h:
`J = d_x / h`, `K = d_y / h`. По умолчанию `XZ_SKEW_FACTOR`,
`YZ_SKEW_FACTOR` = 0; `M852` выводит `J K`, только если они не нулевые.

## Люфт X, Y, Z (`BACKLASH_COMPENSATION`, `M425`)

Компенсация люфта по всем осям, как `M425` в Marlin: ремни X/Y с
растяжением, шпильки Z с обычными гайками (0,05–0,2 мм).

```
M425 X0.1 Y0.08 Z0.1   ; люфт осей, мм (0..5)
M425 F1                ; доля компенсации 0..1 (по умолчанию 1)
M425 S3                ; сглаживание: распределить на 3 мм пути (0 = сразу)
M425                   ; вывести
```

Как в Marlin, у каждой оси есть «долг» коррекции. При смене направления
оси он растёт на люфт × `F` (со знаком направления, не больше одного
люфта). Движения в сторону долга выбирают его:

- `S0` — весь долг в первом же таком движении;
- `S` > 0 — движению достаётся доля путь / `S` (не больше всего долга),
  так что выбор зазора растягивается на `S` мм и не оставляет ступеньки
  на стенке.

Шаги коррекции распределяются по движению алгоритмом Брезенхема и в
позицию не входят: `M114` и координаты не меняются. Ограничения скорости
и ускорения осей учитывают эти шаги. Хоуминг и замеры зондом выбирают
люфт сами: они обнуляют долг и направление. Первое движение оси после
старта без коррекции (направление ещё неизвестно). Babystepping люфт не
учитывает. По умолчанию `BACKLASH_X/Y/Z` = 0, `BACKLASH_SMOOTHING` = 0
(`config/printer.p3steel.h`), всё сохраняется `M500`.

**Как измерить.** Индикатор часового типа на стол (для X/Y — к каретке),
затем `G91`, `G1 X0.5`, `G1 X-0.5`: недоход до исходного показания и есть
люфт. Или печатать тестовую модель (кубик с круглым отверстием,
башню) с разными значениями `M425` и смотреть на швы при смене
направления.

## Лазер и шпиндель (`SPINDLE_LASER`, `M3`/`M4`/`M5`)

Как `LASER_FEATURE` / `SPINDLE_FEATURE` в Marlin, отключается без
`#define SPINDLE_LASER`. Выход — ШИМ таймера на
`SPINDLE_LASER_PWM_PIN` (на P3 Steel PB9 / TIM11 вместо вентилятора
обдува, частота `SPINDLE_LASER_PWM_FREQ`, по умолчанию 1 кГц),
необязательно `SPINDLE_LASER_ENA_PIN` и `SPINDLE_DIR_PIN`
(`*_INVERT`). `S` в единицах 0..`SPEED_POWER_MAX` (по умолчанию 255).

**Шпиндель** (без `LASER_MODE`): `M3 S` — по часовой, `M4 S` — против,
`M5` — стоп. Команды ждут конца движений в очереди, затем
`SPINDLE_POWERUP_DELAY` / `SPINDLE_POWERDOWN_DELAY` мс на разгон и
остановку.

**Лазер** (`LASER_MODE`), мощность привязана к движениям, без остановок:

- `M3 S<p>` — постоянная мощность, лазер горит только во время `G1`/`G2`/
  `G3`, на `G0` и в паузах выключен (inline, как в Marlin);
- `M4 S<p>` — динамическая мощность: пропорционально текущей скорости,
  при разгоне и торможении меньше, на заданной скорости — `S`. Мощность
  пересчитывается раз в 2 мс по скорости шагового прерывания;
- `G1 X.. S<p>` — мощность для этого и следующих движений;
- `M5` — выключить; пустая очередь, `M112` и аварии тоже гасят лазер.

Без `SPINDLE_LASER` `M3`/`M5` по-прежнему для `DC_EXTRUDER`.

## Второй экструдер (`EXTRUDERS 2`, `T0`/`T1`, `M218`)

Как `EXTRUDERS 2` в Marlin: второй мотор экструдера на `E1_STEP_PIN` /
`E1_DIR_PIN` (`E1_INVERT_DIR`, необязательно `E1_ENABLE_PIN`).

- `T0` / `T1` — смена инструмента сразу: ждёт конца движений (и шагов
  linear advance), дальше движения E идут на другой мотор. Сама `T` не
  двигает; следующее движение приводит новое сопло в заданную точку.
- `M218 T1 X Y Z` — положение сопла T1 относительно сопла T0, мм (±500).
  При активном T1 координаты, позиция дома и мягкие ограничения
  сдвигаются на смещение, как в Marlin. Без `X Y Z` — вывести. Хранится
  `M500`, выводится `M503`.
- Общие для обоих: шаги на мм `M92 E`, нагреватель и вентилятор хотэнда,
  K linear advance, координата E. T1 шагает GPIO-импульсами.

**Пины на P3 Steel.** Свободных пинов нет, поэтому что-то надо отключить:
слот драйвера E1 на RAMPS сейчас занят драйвером Z2 (параллельно Z).
Для второго экструдера:

1. оба мотора Z на драйвер Z (параллельно или последовательно) или Z2
   проводами от PB12/PB13;
2. `E1_STEP` на PC15, `E1_DIR` на PC14 — снять кварц 32,768 кГц;
3. не вместе с `Z_STEPPER_ALIGN` (Z2_STEP), `HOTEND_MAX31865` (CS),
   SD-картой на PC14 и пинами ENA/DIR шпинделя — прошивка проверяет это
   при сборке (`#error`).

```
#define EXTRUDERS                2    // config/board.blackpill_p3steel.h
```

## Драйверы TMC2208/2209 по UART (`TMC_UART`, `M906`, `M569`, `M122`)

Как TMC в режиме UART в Marlin, отключается без `#define TMC_UART`:

| Команда | Действие |
|---|---|
| `M906 X800 Y800 Z800 E600` | Рабочий ток, мА RMS (100..2000); ток удержания — `TMC_HOLD_MULTIPLIER` от него (0,5). Без параметров — вывести. |
| `M569 S1 X Y` / `M569 S0 E` | stealthChop (тихо) / spreadCycle по осям; без осей — все. Без `S` — вывести. |
| `M122` | Состояние драйверов: тип, ток, микрошаг, режим, `CS_ACTUAL`, перегрев, КЗ, обрыв фазы, пониженное питание. |

Ток и режимы хранятся `M500` и выводятся `M503`; по умолчанию
`TMC_CURRENT_X/Y/Z` = 800, `TMC_CURRENT_E` = 600, stealthChop на X/Y/Z
(`TMC_STEALTHCHOP` = 0x07).

При настройке драйвер получает:

- `GCONF` — управление по UART, микрошаг из регистра, внутренний
  опорный ток;
- `IHOLD_IRUN` — из тока и `TMC_RSENSE` (0,11 Ом), для малых токов
  `vsense`, формулы как в Marlin;
- `CHOPCONF` — `TOFF` 3, `HSTRT` 1, `HEND` −1, `TBL` 24 такта,
  `TMC_MICROSTEPS` (32: шаги на мм конфигурации P3 Steel не меняются),
  интерполяция до 1/256;
- `PWMCONF` — stealthChop с автоподстройкой, `TPOWERDOWN` 128.

Каждая запись проверяется счётчиком `IFCNT`.

Без питания моторов драйверы не отвечают и забывают настройки. Поэтому:

- раз в секунду (при включённом БП) прошивка читает `GSTAT` и после
  сброса или провала питания настраивает драйвер заново
  (`echo:TMC Y reset, configured`);
- первое движение после включения БП ждёт настройки;
- пропавший драйвер — `echo:TMC E not responding`.

**Подключение.** Один провод: `TMC_UART_TX_PIN` через 1 кОм на
`PDN_UART` всех драйверов. У TMC2209 адреса задаются пинами MS1/MS2
(X 0, Y 1, Z 2, E 3). У TMC2208 адрес только 0: на проводе один
драйвер, задайте только его `TMC_*_ADDR`. Полудуплекс USART (`HDSEL`),
пин open-drain с подтяжкой, эхо своей передачи прошивка пропускает.

**Пины на P3 Steel.** Свободный USART один — USART2 на PA2, это UART
хоста. `TMC_UART 2` отключает его (`NO_SERIAL_UART`), хост тогда только
по USB. На другой плате подойдёт любой свободный USART 1, 2 или 6 с
`TMC_UART_TX_PIN`.

```
#define TMC_UART                 2    // config/board.blackpill_p3steel.h
```

## Качество печати: углы, расход, поток с хоста, калибровка

### Junction deviation (`M205 J`)

Скорость на стыке движений считается как в Marlin
(`JUNCTION_DEVIATION_MM`): угол проходится по дуге, которая отходит от
вершины не дальше `J`, с центростремительным ускорением движения:

```
v² = a · J · sin(θ/2) / (1 − sin(θ/2))
```

- `θ` — угол между движениями по единичным векторам, без тригонометрии;
- `a` — меньшее из ускорений двух движений, ограниченное `M201` осей в
  направлении излома.

Отрезки кривых короче 1 мм с поворотом меньше 45° дополнительно
ограничены скоростью дуги через них: `v² = a · длина / угол поворота`.
Это центростремительное ускорение самой кривой, поэтому окружность
радиусом r проходится со скоростью не выше √(a·r).

В отличие от рывка по осям (`M205 X Y Z`), скорость в углу одинакова в
любом направлении, а на мелких сегментах нет ни звона, ни лишних
замедлений. Рывок остаётся:

- для E (`M205 E`) всегда;
- для всех осей на стыках без движения X/Y/Z (ретракт после печатного
  хода).

`M205 J0` возвращает классический рывок.

На P3 Steel `JUNCTION_DEVIATION` = 0,02 мм. При 1000 мм/с² это 7 мм/с в
углу 90° и 16 мм/с в 45°. С input shaping можно больше: 0,05 мм дают 11 и
25 мм/с.

### Замедление при пустеющей очереди (`M205 B`)

Как `SLOWDOWN` в Marlin. Хост по USB иногда не успевает с потоком мелких
отрезков: очередь пустеет, принтер останавливается, на остановке капля.

Пока в очереди меньше `SLOWDOWN_MOVES` движений (по умолчанию четверть,
16 из 64), короткие движения удлиняются:
`t += 2·(B − t) / в_очереди`. Очередь снова наполняется. Работает только
для `G0`/`G1` с хоста: дуги и файлы с SD или SPI flash заполняют очередь и
так.

`MIN_SEGMENT_TIME` = 20000 мкс, `M205 B0` — выключено.

### Объёмный расход (`M200 D S L`)

- `M200 D1.75` — диаметр филамента и объёмный режим E: значения E в мм³,
  как в Marlin. `D0` или `S0` — обычные мм.
- `M200 L12` — предел объёмной скорости, мм³/с (`VOLUMETRIC_EXTRUDER_LIMIT`
  в Marlin). Печатные движения (X/Y/Z с подачей E) замедляются там, где
  хотэнд не успел бы расплавить пластик: `F ≤ L · 60 / (мм³ на мм пути)`.
  Учитывается `M221`. Холостые ходы и ретракты не ограничиваются.

Ориентиры: E3D V6 / Prusa V6 около 11–15 мм³/с, Volcano около 25.
`VOLUMETRIC_SPEED_LIMIT` = 0 (выключено), `FILAMENT_DIAMETER` = 1,75.
Хранится `M500`.

### Гибридный режим TMC (`M913`)

На осях со stealthChop (`M569 S1`) драйвер переключается на spreadCycle
выше заданной скорости (`TPWMTHRS`, формула Marlin): тихо на малых
скоростях, полный момент на больших.

- `M913 X100 Y100 Z3 E30` — пороги в мм/с, `0` — stealthChop всегда;
- по умолчанию в конфигурации платы X/Y 100, Z 3, E 30;
- `M122` показывает `stealthChop up to 100 mm/s`;
- `M92` пересчитывает пороги.

### Модель хотэнда (`HOTEND_MPC`, `M306`)

Model predictive control, как `MPCTEMP` в Marlin, вместо PID хотэнда.
Модель из двух масс:

- блок нагревателя: теплоёмкость `C`, мощность `P`, потери `A`, с
  вентилятором обдува — до `F`;
- датчик, который догоняет блок с отзывчивостью `R`.

Каждые 100 мс модель делает шаг и подтягивается к измерению, а разница
медленно двигает «окружающую температуру»: она работает как интеграл,
без накопления. Мощность складывается из трёх частей:

- довести блок до цели за 2 с;
- потери при цели;
- нагрев филамента: скорость E × `H` × (цель − окружающая).

Поэтому при включении обдува или смене скорости печати мощность меняется
сразу, до того как температура просядет.

Настройка:

1. `M306 P40` — мощность картриджа, Вт.
2. `M306 T` — остывание с вентилятором, нагрев на полной мощности до
   200 °C (`S` — другая температура), удержание без обдува и с ним. По
   подгонке экспоненты получаются `C`, `R`, `A`, `F`. Около 5 минут,
   `M108` прерывает.
3. `M500`.

Значения по умолчанию — из Marlin (E3D V6, 40 Вт). Опция в
`printer.p3steel.h` выключена: сначала `M306 T`.

### Сетка стола: подразбиение и `G26`

**Подразбиение** (`MESH_SUBDIVISIONS`, как `ABL_BILINEAR_SUBDIVISION` в
Marlin):

- из измеренных точек сплайном Catmull-Rom строится виртуальная сетка с
  `MESH_SUBDIVISIONS` точками на ячейку;
- на P3 Steel 3: сетка 3×3 становится 7×7;
- между виртуальными точками интерполяция билинейная, движения режутся
  по виртуальным линиям;
- Z идёт по гладкой поверхности, без изломов на линиях сетки;
- за краем сетки значение постоянное, как раньше; `1` — обычная сетка.

**`G26`** — тестовая печать сетки, как в Marlin: круги в узлах сетки и
линии между ними, один слой.

```
G26 H215 B60 L0.2 S0.4 P5
```

- `H` — хотэнд (по умолчанию текущая цель или 205);
- `B` — стол (текущая цель или 60, `B0` — не греть);
- `L` — высота слоя, `S` — ширина линии;
- `P` — длина подачи перед началом;
- `K` — не выключать нагрев после печати.

Включает выравнивание на время печати. Нужны хоуминг и сетка. `M410`
останавливает печать. Если линии в какой-то зоне тонкие или размазанные,
поправьте эту точку `M421` или Z-offset.

### Скручивание оси X (`M423`)

Как `X_AXIS_TWIST_COMPENSATION` в Marlin. Провисающая или скрученная
балка X наклоняет зонд относительно сопла, и в разных местах по X зонд
видит стол выше или ниже, чем сопло.

- К замерам зонда (`G29`, `G30`, `G34`) прибавляется поправка по
  `TWIST_POINTS` точкам (3, до 7) от `X_TWIST_START` до `X_TWIST_END`
  (положение зонда), линейно между ними и за краями.
- `M423 X<точка> Z<мм>` задаёт поправку, `M423 R` сбрасывает, `M423`
  выводит точки с их X.

Как измерить: в каждой точке `G30` (зонд), затем опустить сопло на
бумагу. Поправка = Z сопла минус результат `G30`.

### Калибровочные печати (`M9910`, `M9911`, `M9912`)

**`M9910` — узор linear advance.** Команда своя, в Marlin такой нет.

```
M9910 A0 B0.1 C0.01
```

- По линии на каждое K от `A` до `B` с шагом `C`, до 30 линий, первая
  спереди, через 5 мм.
- Каждая линия: 20 мм медленно (`W`, 20 мм/с), 40 мм быстро (`V`,
  100 мм/с), 20 мм медленно.
- Нужное K — у линии с ровной шириной на смене скорости, без тонкого
  начала и капли в конце быстрого участка; задаётся `M900 K`.
- K каждой линии выводится. Хотэнд нагреть заранее, нужен хоуминг.

**`M9911` — башня input shaping.**

```
M9911 A15 B80 H50
```

- Однослойная стенка квадратом 50 мм, печать на `V` мм/с (100).
- Частота `M593` для X и Y растёт от `A` до `B` Гц по высоте `H` мм;
  текущая частота выводится каждые 5 мм.
- Высота с наименьшим звоном после углов даёт частоту для `M593 F`
  (звон по X — на стенках вдоль Y, и наоборот).
- После печати прежние настройки восстанавливаются.

**`M9912` — tuning tower для любой модели из слайсера** (как
`TUNING_TOWER` в Klipper): параметр становится `A + B · Z` (мм) с каждым
`G0`/`G1`.

| `P` | Параметр |
|---|---|
| 1 | K linear advance |
| 2 | частота input shaping |
| 3 | junction deviation |
| 4 | температура хотэнда |
| 5 | поток, % |
| 6 | ускорение печати |

`C` — полоса: значение меняется раз в `C` мм (середина полосы).
`M9912 P0` — выключить. Не сохраняется: после печати `M501`.

```
M9912 P4 A230 B-1 C5    ; башня температур: 230 °C внизу, −1 °C на мм, ступени по 5 мм
```

Все тестовые печати идут через тот же путь, что `G1` (с сеткой стола).
E относительный, координата E хоста не меняется.

## Прошивочный ретракт (`FIRMWARE_RETRACT`, `G10`, `G11`, `M207`, `M208`)

Как `FWRETRACT` в Marlin: слайсер вместо движений E пишет `G10` (ретракт)
и `G11` (возврат), а длина и скорости задаются в прошивке и меняются на
ходу, без перенарезки модели.

| Команда | Действие |
|---------|----------|
| `G10` | Ретракт: E назад на `M207 S` со скоростью `M207 F`, затем подъём Z на `M207 Z`. Повторный `G10` без `G11` игнорируется. |
| `G11` | Опустить Z, подать `M207 S` + `M208 S` со скоростью `M208 F`. Без предшествующего `G10` игнорируется. |
| `M207 S<мм> F<мм/мин> Z<мм>` | Длина, скорость ретракта, подъём Z. |
| `M208 S<мм> F<мм/мин>` | Дополнительная подача после возврата (может быть отрицательной), скорость возврата. |

- Координаты G-кода не меняются: `M114` показывает те же E и Z, следующие
  абсолютные `G1 E…` продолжаются так, будто ретракта не было.
- Подъём Z держится для всех движений до `G11` (он входит в поправку Z
  вместе с сеткой и babystepping), холостой ход идёт поднятым.
- Движения только E идут с ускорением `M204 R`; поток `M221` на ретракт
  не действует.
- `G28` сбрасывает состояние ретракта.
- По умолчанию (P3 Steel): 1 мм, 25 мм/с, без подъёма; `M500` сохраняет.

В PrusaSlicer: Printer Settings → Extruder → Retraction → «Use firmware
retraction». Длина в слайсере тогда не используется.

## Шаговый путь в ОЗУ (`STEP_CODE_IN_RAM`)

Опция по умолчанию выключена. В ОЗУ переносятся прерывание TIM5,
`queue_step()`, `dda_step()`, `dda_start()`, `timer_set()` и
`timer_step_pulse_end()`. В IAR это `__ramfunc`: в ICF нужна строка
`initialize by copy { readwrite };`.

**Почему выключено.** На Cortex-M4 код из SRAM выбирается по той же шине,
что и данные. Поэтому при включённом ускорителе ART во Flash выигрыш не
гарантирован. Решайте по замеру `M9001` на плате.

## IAR: оптимизация

Время-критичные функции помечены макросом `TEACUP_HOT` (`hal/arch.h`). В
IAR он разворачивается в `#pragma optimize=speed`. Помечены:

- шаговое прерывание и `timer_set()`;
- `queue_step()`, `dda_step()`, `dda_start()`, `dda_clock()`,
  `dda_create()`;
- математика движения (`dda_maths.c`) и lookahead;
- прерывания UART, SysTick, PendSV, концевиков.

**Как настроить проект IAR:**

1. **Весь проект:** Options → C/C++ Compiler → Optimizations →
   **Level: High**, **Goal: Balanced** (или **Size**, если нужно
   сэкономить Flash). Уровень High обязателен: `#pragma optimize` не может
   поднять уровень выше заданного для файла, она меняет только цель
   (speed/size). На уровнях Low и Medium `TEACUP_HOT` ничего не делает.
2. **Multi-file compilation** (Options → C/C++ Compiler → Multi-file
   Compilation) для группы с файлами `motion/*.c` и `hal/timer.c` (или
   для всего проекта). По замерам ниже это даёт больше, чем выбор цели
   speed/size. При необходимости включите «Discard unused publics».
3. **По желанию:** для той же группы Override inherited settings →
   Level High, Goal Speed.

## SD-карта: Petit FatFs R0.03a

В `pff/` лежит Petit FatFs R0.03a (релиз ChaN от 30.01.2019) с доработками
Teacup, подробный список — в начале `pff.c`:

- `pf_parse_line()` и `disk_parsep()` читают файл построчно в парсер
  G-кода без буфера на сектор;
- `pf_unmount()`;
- новый результат `FR_END_OF_FILE`;
- `pf_parse_line()` не читает дальше конца файла, пропускает пустые
  строки, выполняет последнюю строку без перевода строки, а перевод
  строки (выполнение команды) передаёт парсеру, когда карта уже отпущена;
- файлы переименованы в `pff_diskio.*` и `pff_conf.h`;
- код собирается только при `#ifdef SD`.

В R0.03a опции переименованы на новый формат (`PF_USE_READ`,
`PF_FS_FAT32` и т.д.), типы берутся из `stdint.h`.

## Функции, которые на STM32F4 не поддерживаются

Эти опции дают `#error` с пояснением:

- `EECONFIG` (EEPROM нет; вместо неё — `M500`/`M501`, см. выше)
- `TEMP_INTERCOM` (платы Gen3, только AVR)
- `TEMP_PT100`

## Программа для компьютера: Teacup Host (`host/`)

В каталоге `host/` — программа для Windows на WPF (.NET 8), аналог
Pronterface с современным интерфейсом: проверка принтера (оси, нагрев,
концевики, PID, макросы), печать с компьютера через COM-порт или по сети
